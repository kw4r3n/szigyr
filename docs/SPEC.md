# STS 言語仕様 v0（草案）

STS は仮称。この文書が言語の唯一の規範である。
**許可リスト方式**: この文書に明記された構文と組み込みだけを受理する。それ以外は拒否する（E1000 / E2000）。

## 0. 原則

1. **構文は TypeScript と完全互換。** ソースは TS のパーサでそのまま解析できる。
2. **意味は変えない、絞るだけ。** 受理されたプログラムの意味は「§10 の変換を施した JS の挙動」と定義する。禁止とトラップ以外に、JS と異なる計算結果を生む規則はない。例外は §14.7 の C 専用のプログラム。
3. **managed 層は常に JS エンジン上で動く。** C に変換されるのは strict / rt 層だけ。C 側は JS 側と観測上一致しなければならない（戻り値、借用引数への書き込み、トラップの種類と位置）。C 専用のプログラム（§14.7）には比べる JS 側がない。
4. **関数境界はすべて明示。** 推論するのはローカル変数の型と、呼び出しの型引数だけ。例外は、戻り値の注釈のないアロー関数と関数式の戻り値の型（§3.2）。
5. **未定のことを実装が決めない。** 未定の項目は §13。

## 1. モジュール

- ESM のみ。名前付きの `import` / `export` だけ。default export、`export *`、動的 import、`require` は禁止。
- 相対 import は拡張子 `.ts` まで書く。`import { parse } from "npm:yaml"` の形は §7.4、`"c:…"` の形は §14.1。
- モジュール直下に書けるのは次だけ。
  - `import` / `export`
  - `function` 宣言、`type`、`interface`、`class`
  - `const`（初期化式は、リテラル、または不変なレコード・配列のリテラル。型注釈必須）
  - `test(...)` の呼び出し（§9.2）
  - `declare module "c:…" { … }`（§14.1）
- モジュール直下の `let`、および可変な値を持つ `const` は禁止（E5002）。
- `import` してから `export` する再 export は、何段つないでもよい。循環していて名前を解決できなければ、その名前を使う位置が E2000（Q226）。
- §12 の組み込み名と §13 の予約名は予約されている。同名の宣言は禁止（E1000）。組み込みは import なしで使える。

## 2. 層

層は指示子（文字列だけの文）で決まる。関数本体の先頭に書くとその関数に、ファイルの先頭に書くとそのファイルの全関数に適用される。

| 指示子 | 層 | 概要 |
| --- | --- | --- |
| なし | managed | JS エンジン上で動く。GC あり |
| `"use owned"` | strict | 所有権で管理。GC なし。C に変換される |
| `"use rt"` | rt | strict からメモリ確保・権限・再帰を除いたもの |
| `"use unsafe"` | （層ではない） | strict / rt の関数に重ねる修飾（§14.4） |

呼び出しの規則（違反は E4001）。

| 呼び出し元 ＼ 呼び出し先 | managed | strict | rt | rt かつ unsafe |
| --- | --- | --- | --- | --- |
| managed | 可 | 可 | 可 | 不可 |
| strict | 不可 | 可 | 可 | 不可 |
| rt | 不可 | 不可 | 可 | 不可 |
| rt かつ unsafe | 不可 | 不可 | 可 | 可 |

- strict かつ unsafe の関数は、この表では strict として扱う。rt かつ unsafe の関数の列は Q205（§14.3）。

- アロー関数と関数式は、外側の関数の層に属する。指示子は書けない。
- strict / rt では、外側の変数を捕捉する関数（クロージャ）は禁止（E4003）。関数値も禁止。例外は `ensures` の引数（§9.1）と、関数型パラメータ（§3.3。実行時の値ではなく、コンパイル時の特殊化）。
- strict / rt で使える型は §3.3 の型だけ（違反は E4002）。

## 3. 型

### 3.1 プリミティブと数値

- `boolean`、`string`（managed のみ）、`null`、`void`、`unknown`（managed のみ）、`never`。`undefined` は存在しない。
- 数値型: `f64`、`f32`、`i8`、`i16`、`i32`、`u8`、`u16`、`u32`、`usize`。
  - `number` は `f64` の別名。
  - `usize` は添字と長さの型。v0 では値の範囲は `u32` と同じ（0 〜 2^32−1）だが、`u32` とは別の型。
  - `i64`、`u64`、`bigint` は予約。
- **暗黙の数値変換はない。** 変換は型と同名の関数で行う: `i32(x)`、`f32(x)`、`usize(x)` など。
  - 整数型への変換は、値が整数でない、または範囲外ならトラップ（T003）。
  - `f32(x)` は最も近い binary32 に丸める。整数から浮動小数への変換は正確。
- **数値リテラルは文脈の型になる**（代入先、もう一方のオペランド、仮引数の型）。文脈がなければ `f64`。整数型の文脈で、非整数または範囲外のリテラルはコンパイルエラー（E2008）。
- 算術。
  - `+`、`-`、`*`: 両辺は同じ数値型（違えば E2003）。整数型で結果が範囲外ならトラップ（T001）。
  - `/`、`**`: 浮動小数型のみ。整数型の `/` は禁止（E2007）。
  - `%`: 浮動小数型のみ。
  - 整数の除算は `divTrunc(a, b)`（0 方向に切り捨て）と `rem(a, b)`。`b` が 0 ならトラップ（T007）。`divTrunc` は結果が範囲外ならトラップ（T001）。`rem` の結果は常に範囲内で、`rem(MIN, -1)` は 0 を返す（トラップしない）。整数型に -0 はなく、整数演算の結果の -0 は +0 にそろえる（Q090）。
  - 折り返し演算は `wrapAdd(a, b)`、`wrapSub(a, b)`、`wrapMul(a, b)`（同じ整数型）。
  - 単項 `-`: 符号つき整数と浮動小数のみ。結果が範囲外ならトラップ（T001）。
  - `++`、`--` は禁止。`+= 1` と書く。複合代入 `+=`、`-=`、`*=` は対応する演算と同じ規則。
  - `f32` の演算結果は、1演算ごとに binary32 に丸める。
- 比較 `<`、`<=`、`>`、`>=`、`===`、`!==`: 両辺は同じ型。`==`、`!=` は禁止（E1002）。
- ビット演算 `&`、`|`、`^`、`~`、`<<`、`>>`、`>>>`: `i32` と `u32` のみ。
  - `>>` は `i32` のみ（算術シフト）。`>>>` は `u32` のみ（論理シフト）。
  - シフト量は同じ型で 0 〜 31。範囲外はトラップ（T009）。
  - `<<` であふれたビットは捨てる（トラップしない）。
- 条件式（`if`、`while`、`for`、三項演算子、`&&`、`||`、`!`）のオペランドは `boolean` のみ（E2004）。

### 3.2 managed の複合型

- **レコード**: `type P = { readonly x: f64; y: f64 }`。閉じた正確な型。余剰プロパティ不可、幅による部分型なし。省略可能プロパティ（`?`）は禁止（E1008）。
- **タグつき union**: 各メンバがレコードで、共通フィールド `kind` に互いに異なる文字列リテラル型を持つ。絞り込みは `x.kind === "..."` と `switch (x.kind)`。`switch` は全メンバを網羅すること（E2005）。
- **文字列リテラルの union**: `type Color = "red" | "green"`。
- **`T | null`**: 絞り込みは `x === null` / `x !== null`。`??` と `?.` を使える。
- 上記以外の union と intersection は禁止。
- **コレクション**: `Array<T>`（不変）、`ReadonlyArray<T>`（共変）、`Map<K, V>`、`Set<T>`。`K` と `Set` の `T` は `string`、数値型、`boolean`、文字列リテラル型、文字列リテラル型だけの union のみ。ほかの union は E2002（Q081）。
  - `T[]` という書き方は禁止。`Array<T>` に統一する。
  - 添字と `length` の型は `usize`。添字アクセスは範囲検査され、範囲外はトラップ（T002）。
  - タプル型と配列の分割代入は禁止。
- **関数型**: `(a: A) => B`。managed のみ。引数は反変、戻り値は共変。
- **戻り値と末尾**: 戻り値の型が `void` でない関数が末尾に到達しうるなら E2002（Q023）。戻り値の注釈のないアロー関数と関数式は、`return` の型から戻り値の型を推論する（Q126）。推論した型が `void` でなければ、同じく末尾に到達しうると E2002（Q221）。アンカーは関数名、アロー関数なら `=>`。
- **class**: 継承なし（`extends` 禁止）。フィールドは型つきで宣言する。`private`、`readonly`、`static`、`implements` は可。getter / setter、省略可能メンバ、index signature、`abstract`、`#private` は禁止。メソッドは呼び出し位置でしか参照できない（`const f = obj.m` は禁止）。
- **interface**: メソッドのシグネチャだけを持つ。class が `implements` で明示的に実装する。構造的な適合は認めない。`extends` は禁止。1 つの interface に同じ名前のメソッドを 2 つ書けない（E1000、Q223）。
- **ジェネリクス**: 関数、`type`、`class`、`interface` に型引数を書ける。制約は `T extends I`（`I` は interface）だけ。既定の型引数は禁止。
- **`unknown`**: 使うには `cast<T>(x): Result<T, CastError>` で実行時に検証する。`T` はプリミティブ、レコード、タグつき union、`Array`、`T | null` の組み合わせに限る。
- **文字列**: JS の文字列そのまま（`length` は UTF-16 の符号単位数）。strict / rt 層に文字列型はない。

禁止する型機能（E1004 〜、なければ E1000）:
`any`、`object`、`Function`、`{}`、`symbol`、`enum`、`namespace`、`as`（`as const` を含む）、非 null 表明 `!`、`satisfies`、型述語（`x is T`）、関数オーバーロード、宣言のマージ、`declare`（§14.1 の `declare module` を除く）、conditional / mapped / template literal / indexed access 型、`keyof`、型の `typeof`、ユーティリティ型（`Partial` など）、省略可能引数、既定引数、残余引数。

### 3.3 strict / rt の型

- 数値型、`boolean`。
- **`Struct<{ ... }>`**: 値型。`type V3 = Struct<{ readonly x: f32; readonly y: f32; readonly z: f32 }>`。
  - フィールドの型は、数値型、`boolean`、他の `Struct`、`Vec<T>`、`Pool<T>`、`Handle<T>`、`Arena`、`ArenaBuf<T>`、`RingTx<T>`、`RingRx<T>`（§15.1）、`CHandle<T>`（§14.5）。
  - 値はオブジェクトリテラルで作る（型注釈のある文脈で）。
  - **Copy の判定**: 全フィールドが `readonly` で、かつ全フィールドの型が Copy なら、その Struct は Copy。それ以外は移動のみ（所有型）。数値型と `boolean` は Copy。
- **`Vec<T>`**: 所有される可変長配列。`T` は Copy 型のみ（v0）。所有型。

  | 操作 | 受け手の借用 | 確保 | 備考 |
  | --- | --- | --- | --- |
  | `Vec.create<T>(alloc: Alloc, capacity: usize): Vec<T>` | — | あり | 長さ 0 で作る |
  | `v.length` | Ref | なし | `usize` |
  | `v[i]`（読み） | Ref | なし | 範囲外は T002 |
  | `v[i] = x`（書き） | Mut | なし | 範囲外は T002 |
  | `v.push(x)` | Mut | あり | |
  | `v.pop(): T \| null` | Mut | なし | |
  | `v.clear()` | Mut | なし | |
  | `v.fill(x)` | Mut | なし | |
  | `v.slice(start, end)` | Ref / Mut | なし | 実引数の位置でのみ書ける（§5.5）。代入の左辺の添字（`v.slice(0, 4)[0] = x`）も E3004 |

- **`Slice<T>`**: `Vec<T>` の連続部分への借用ビュー。型としては `Ref<Slice<T>>` / `Mut<Slice<T>>` の形で、パラメータにだけ現れる。`s.length`、`s[i]`、`s.fill(x)`、`s.slice(a, b)` を使える。
  - `Vec<T>` の変数（または `Ref<Vec<T>>` / `Mut<Vec<T>>` のパラメータ）は、`Ref<Slice<T>>` / `Mut<Slice<T>>` のパラメータにそのまま渡せる。全体へのビューになる。
  - `v.slice(start, end)` は `start <= end <= v.length` でなければトラップ（T002）。
- **`Pool<T>`**: 固定容量のプール（Q188 (a)）。所有型。`T` は Copy 型のみ（条件と違反のコードは `Vec<T>` と同じ）。
  - **`Handle<T>`**: プールの要素を指す Copy 型のハンドル。値は不透明で、メンバはない。ハンドルどうしの比較（`===` など）はできない。`Vec` の要素、Struct のフィールド、`T | null` に置ける。配置は §10.2。

  | 操作 | 受け手の借用 | 確保 | 備考 |
  | --- | --- | --- | --- |
  | `Pool.create<T>(alloc: Alloc, capacity: usize): Pool<T>` | — | あり | 伸びない。容量は `capacity` で固定 |
  | `p.insert(x: T): Handle<T> | null` | Mut | なし | 満杯なら `null` |
  | `p.get(h: Handle<T>): T` | Ref | なし | 無効なハンドルは T011 |
  | `p.set(h: Handle<T>, x: T): void` | Mut | なし | 無効なハンドルは T011 |
  | `p.remove(h: Handle<T>): T` | Mut | なし | 取り除いた値を返す。無効なハンドルは T011 |
  | `p.has(h: Handle<T>): boolean` | Ref | なし | トラップしない |
  | `p.length` | Ref | なし | `usize` |
  | `p.capacity` | Ref | なし | `usize` |

  - 無効なハンドルとは、取り除いた後のもの、別のプールのもの、範囲外のものをいう。`get` / `set` / `remove` が T011 でトラップし、位置はメンバ名である。
  - 空きの枠は最初は添字の小さい順に使い、取り除いた枠は後入れ先出しで再利用する。プールとアリーナの番号は、ホスト（JS）の 1 つのカウンタで 1 から振る。世代は `u32` で、枠を再利用するたびに 1 増やし、桁あふれしたら 0 に戻る（Q188 の「決めた詳細」）。
- **`Arena`**: 区切りでまとめて解放するアリーナ（Q188 (b)）。所有型。
  - **`ArenaBuf<T>`**: アリーナの中の領域を指す Copy 型のハンドル。`T` は Copy 型のみ（条件と違反のコードは `Vec<T>` と同じ）。値は不透明で、メンバは `length` だけ。ハンドルどうしの比較（`===` など）はできない。`Vec` の要素、Struct のフィールド、`T | null` に置ける。配置は §10.2。

  | 操作 | 受け手の借用 | 確保 | 備考 |
  | --- | --- | --- | --- |
  | `Arena.create(alloc: Alloc, bytes: usize): Arena` | — | あり | ホストに `bytes` バイトの領域を 1 回だけ作らせる |
  | `a.alloc<T>(n: usize, init: T): ArenaBuf<T> | null` | Mut | なし | 使用済みの位置を `T` の整列（§10.2）に切り上げ、`n` 要素ぶんを取り、全要素を `init` で埋める。残りが足りなければ `null` で、位置は動かさない。`T` が型パラメータであるか、型パラメータを含むときは、全層で E2002（Q215）。要素のバイト数を JS と C で同じに決めるため |
  | `a.view(b: ArenaBuf<T>): Slice<T>` | パラメータと同じ | なし | 実引数の位置にだけ書ける（ほかは E3004）。パラメータの型に応じて `Ref<Slice<T>>` か `Mut<Slice<T>>` になり、受け手のアリーナも同じモードで借用する |
  | `a.reset(): void` | Mut | なし | 世代を 1 増やし（`u32` で折り返す）、使用済みの位置を 0 に戻す。中身は消さない |
  | `a.remaining` | Ref | なし | 残りのバイト数（`usize`） |
  | `b.length` | — | なし | 要素数（`usize`）。アリーナなしで読める |

  - 無効なハンドルとは、`reset` の前に取ったもの、別のアリーナのものをいう。`view` が T012 でトラップし、位置はメンバ名 `view` である。番号と世代の検査はビューを作るときの 1 回だけで、要素の読み書きには入らない。
  - アリーナの番号はプールと共有のカウンタで振る（上の `Pool` の項）。世代は `reset` のたびに 1 増やし、桁あふれしたら 0 に戻る。折り返すと古いハンドルを見逃しうるが、プールと同じく論理の誤りとして扱う（読み書きは範囲内の Copy 値なので、メモリ安全性と排他性は崩れない）。
  - 1 つの呼び出しに同じアリーナのビューを 2 つ渡す形は、§5.5 の実行時の重なり検査（T013）の対象になる。アリーナの中の領域は `Vec` ではないので、`push`、`pop`、長さの変更はできず、`Vec` のパラメータにも渡せない（`Slice` のパラメータには渡せる）。
- **要素の配置**（Q229）: strict / rt では、`Vec`、`Slice`、`Pool`、`Handle`、`ArenaBuf`、`RingTx`、`RingRx` と `Arena.alloc` の要素の型に §10.2 のバイト配置がなければ E4002。`null` だけの型と、それを含む型（`Result<null, E>`、`null` のフィールドを持つ Struct など）が当たる。strict / rt のジェネリックな関数の型引数が要素になるときは、呼び出しの型引数が同じ条件を満たすこと（違反は E4002。アンカーは呼び出し先の名前か型引数）。managed のコードにはこの制限がない。managed の `Vec<null>` は JS の配列で、C には渡らない（渡す先の strict / rt の関数の型が E4002 になる）。
- **関数型パラメータ**: strict / rt の関数のパラメータの型にだけ、関数型 `(x: A) => R` を書ける（その関数型のパラメータの型としても書ける。戻り値の型には書けない）。それ以外の位置（戻り値、ローカル変数、フィールド、型引数）は E4003。
  - 実引数に書けるのは、モジュール直下（import を含む）のジェネリックでない strict / rt の関数の名前か、呼び出し元自身の同じ型の関数型パラメータだけ。ほかの式は E4003。型はパラメータと戻り値の型が完全に一致すること（不一致は E2002）。
  - 層: rt の関数の関数型パラメータには rt の関数だけ、strict の関数のパラメータには strict か rt の関数を渡せる。managed の関数は渡せない（違反は E4001）。managed から関数型パラメータを持つ strict / rt の関数を呼ぶときも、実引数は strict / rt の関数の名前に限る。
  - 関数型パラメータは、呼ぶか、別の呼び出しの関数型パラメータへそのまま渡すことしかできない。ほかの使い方は E4003。
  - C では実引数の関数の組ごとに単相化する（D104 の鍵に足す）。実行時に関数値は存在しない。rt の再帰（E4005）とトラップの一覧（§6）は、具体化ごとの呼び出しグラフで判定する。
- **`Ref<T>` / `Mut<T>`**: 借用（§5.5）。
- **`RingTx<T>`、`RingRx<T>`、`RingPair<T>`**: リングバッファ（§15.1）。**`CHandle<T>`**: C のポインタを持つ所有型（§14.5）。**`Ptr<T>`、`ConstPtr<T>`、`CType<"X">`**: unsafe の関数の中だけで使える（§14.4）。
- **タグつき union** と **`T | null`**: メンバや `T` が Copy 型のときに限り使える。`Result<T, E>` も同じ条件。
- strict / rt の関数の型引数は、この節の型に限る。

## 4. 文と式

- `var` は禁止（E1001）。`let` は初期化必須。
- 使える制御構文: `if` / `else`、`while`、`do` / `while`、`for (;;)`、`for (const x of ...)`、`switch`（網羅必須）、`break`、`continue`、`return`。ラベルは禁止。
- `for...of` の対象は `Array`、`ReadonlyArray`、`Set`、`Map` の `keys()` / `values()`。
- `throw`、`try`、`catch`、`finally` は禁止（E1007）。回復不能なエラーは `panic(msg)`、回復可能なエラーは `Result`。
- `async` / `await` は managed のみ。
- 分割代入は、レコードの `const { x, y } = p` だけ。
- オブジェクトのスプレッド `{ ...a, x: 1 }` は、結果が注釈の型と正確に一致するとき可。配列のスプレッドは managed で可。
- 1 つのオブジェクトリテラルに同じキーを 2 回書けない（短縮形 `{ a }` を含む。E1000、Q223）。間にスプレッドがあっても、明示したキーの 2 回目は E1000（`{ a: 1, ...s, a: 9 }`）。スプレッドの元にあるキーを後の明示したキーで上書きするのは可（`{ ...s, a: 9 }`）。
- テンプレートリテラルは managed で可（タグつきは禁止）。
- 禁止: `with`、`eval`、`delete`、`in`、`instanceof`、値の `typeof`、`void` 演算子、カンマ演算子、`arguments`、ジェネレータ、`new Function`、`Proxy`、`Reflect`、`Symbol`、`for...in`、`this` のクラス外での使用。

## 5. 所有権

### 5.1 用語

- **Copy 型**: 数値型、`boolean`、Copy の Struct、Copy 型だけからなる union、`Handle<T>`、`ArenaBuf<T>`、`Ptr<T>`、`ConstPtr<T>`（§14.4）。代入や引数渡しで複製される（どちらも不変なので、複製か共有かは観測できない）。
- **所有型**: 非 Copy の Struct、`Vec<T>`、`Pool<T>`、`Arena`、`RingTx<T>`、`RingRx<T>`、`CHandle<T>`。ちょうど1つの束縛に所有される。

### 5.2 移動

所有型の値は、次の操作で移動する。

1. 別の変数への代入、または初期化（`const b = a`）。
2. 値渡しパラメータ（型が `Ref` / `Mut` でないパラメータ）への実引数。
3. `return`。
4. Struct リテラルのフィールドへの格納。
5. オブジェクトのスプレッド `{ ...a, x: 1 }` の元（Q053）。所有型のフィールドを持つ値は、スプレッドで複製されない。元に書けるのは、所有しているローカル変数と値渡しのパラメータだけである。`Ref` / `Mut` のパラメータを元にするのは E3004（`const t = s` と同じ）。フィールドパス（`s.inner`）を元にするのは E3003（部分移動と同じ）。アンカーはどちらも元の式の先頭。元の型が Copy 型なら、この制限はない。

移動元の変数は、それ以後使えない（E3001）。`let` 変数は、再代入すればまた使える。

### 5.3 検査

- 検査は制御フローに沿って行う。分岐の一方で移動した変数は、合流後は移動済みとして扱う。
- ループ本体の中で、ループの外で宣言された変数を移動するのはエラー（E3002）。同じ反復の中で必ず再代入される場合は可。
- `?.` の呼び出しと添字アクセスでは、受け手が `null` なら実引数と添字を評価しない。検査は、受け手を評価した直後の状態と、全体を評価した後の状態を合流する（Q220）。そのため、`?.` の実引数の中で移動した変数は合流後に移動済みとみなす。中で再代入しても、前の移動は取り消さない。
- 所有型フィールドだけを取り出す部分移動（`const v = s.buf`）はエラー（E3003）。分解するなら `const { buf, n } = s` で全体を移動する。

### 5.4 破棄

所有型の値は、移動されないままスコープを抜けると破棄される。破棄は観測できない（デストラクタはない）。

### 5.5 借用

パラメータの型に `Ref<T>`（読み取り）または `Mut<T>`（排他的な書き込み）を書く。`T` は所有型か `Slice<U>`。

- **実引数は場所式に限る**（E3008）: ローカル変数、受け取った `Ref` / `Mut` パラメータ、それらのフィールドパス（`s.buf`）、`v.slice(a, b)`、`a.view(b)`。
- `v.slice(a, b)`、`a.view(b)`、`p.slice(n)`、`p.borrow()`（§14.4）を書ける位置は §3.3 と §14.4 のとおり。代入の左辺の添字やフィールド（`v.slice(0, 4)[0] = 1`、`a.view(b)[0] = 1`、`p.borrow().f = 1`）はその位置に当たらず、読む形と同じく E3004（Q222）。
- 呼び出し側には借用の記号を書かない。モードは呼び出し先のシグネチャで決まる。
- 借用で渡した変数は、呼び出しの後もそのまま使える。
- `const` と `let` の違いは再代入の可否だけ。所有していれば `Mut` で渡せる。
- `Ref` で受け取った値を `Mut` に渡すことはできない（E3006）。`Mut` で受け取った値を `Ref` に渡すのは可。
- **排他性**（E3005）: 1つの呼び出しの中で、ある変数を `Mut` で渡すなら、同じ変数を他の実引数（`Ref`、`Mut`、値渡しのいずれでも）に使えない。メソッド呼び出しの受け手も実引数の1つとして数える。
  - 借用の場所はフィールドパスで比べる。同じ根でも、フィールドパスが互いに他方の前置でなければ別の場所とみなす（`f(s.a, s.b)` は可、`f(s, s.a)` と `f(s.a, s.a)` は不可）（Q190）。
  - 1 つの呼び出しの直接の実引数がどちらも同じ根の `v.slice(a, b)` か `a.view(b)` の形なら、静的には重複とみなさず、実行時に調べる。すべての実引数を評価した後、呼び出しの前に、少なくとも一方が `Mut` の組について要素のバイト範囲の重なりを調べ、重なれば T013 でトラップする。長さ 0 の範囲はどれとも重ならない。各 `slice` の T002 と各 `view` の T012 は、その実引数の評価のときに先に出る。根全体やフィールドパスの借用と `slice`、`view` を混ぜた形（`f(v.slice(0, n), v)`）は E3005 のまま（Q190）。
  - 実引数の式の評価結果が Copy 値なら、その式の中の借用は評価が終わった時点で終了する。`v.push(v.length)` は可。
- **二級性**（E3004）: `Ref<T>` / `Mut<T>` 型の値は、
  1. ローカル変数に代入できない。
  2. フィールドや配列の要素に格納できない。
  3. `return` できない。
  4. クロージャに捕捉できない。
  5. 型引数にできない。
  6. 他の関数の `Ref` / `Mut` パラメータに渡すことはできる。

### 5.6 managed 層での所有型

- 所有型の値は、managed 層のコードの中でも §5.2 〜 §5.5 の規則に従う。
- 所有型の値は、managed のレコード、class のフィールド、`Array`、`Map`、`Set`、クロージャの捕捉に入れられない（E3007）。置けるのはローカル変数、引数、戻り値だけ。
- 要素（`Map` ではキーと値）の型が所有型であるか所有型を含む `Array`、`ReadonlyArray`、`Map`、`Set`、`Promise` の型は、書くことも推論されることもできない（E3007）。所有型を返す `async` 関数もこれに当たる（Q174）。例外は `await port.recv()`（§15.2）。
- 長く保持するには `OwnedCell<T>` を使う。`OwnedCell` 自体は managed の値。

  | 操作 | 挙動 |
  | --- | --- |
  | `OwnedCell.create<T>(v: T): OwnedCell<T>` | `v` を移動して入れる |
  | `cell.take(): T` | 取り出す。空ならトラップ（T008） |
  | `cell.put(v: T): void` | 入れる。空でなければトラップ（T008） |
  | `cell.isEmpty(): boolean` | |

## 6. rt 層

strict の規則に加えて、次を禁止する。

- 表で「確保あり」の操作（E4004）。
- 権限型のパラメータ（E4006）。`Alloc` も含む。
- rt 関数の間の再帰（直接・相互とも。E4005）。関数型パラメータを通らない再帰（名前での呼び出しの循環）は、その関数を呼ぶ者がいなくても E4005。関数型パラメータを通る再帰は、実引数を解決した具体化ごとの呼び出しグラフで判定する（§3.3、Q227）。
- `OwnedCell`。

使えるのは、数値演算、Struct、借用した `Vec` / `Slice` の読み書き、借用した `Pool` の `insert` / `get` / `set` / `remove` / `has` / `length` / `capacity`（確保なし。`Pool.create` は確保ありなので使えない）、借用した `Arena` の `alloc` / `view` / `reset` / `remaining`（確保なし。`Arena.create` は確保ありなので使えない）、他の rt 関数の呼び出し、リングの `push` / `pop`（§15.1）。

rt かつ unsafe の関数は、権限なしで C の関数を呼べる（§14.3）。unsafe の操作（§14.4）のうち、`Ptr` と `ConstPtr` のメンバ、`cfn`、`CHandle.create` と `get` も使える。`Ptr.box` と `unbox` は確保ありとして扱う（E4004）。

トラップしうる演算（整数の溢れ、範囲外アクセスなど）は、v0 では許可する。コンパイラは、rt 関数ごとのトラップしうる箇所の一覧を出せること（段階 2）。

## 7. 権限

### 7.1 権限型

`System`、`Alloc`、`Fs`、`Net`、`Clock`、`Random`、`Log`、`Js`、`Ffi`、`Spawn`。いずれも不透明な組み込み型。

- プログラムの入口は `export function main(sys: System): void`（または `Promise<void>`）。
- 個別の権限は `sys.alloc`、`sys.fs`、`sys.clock` のように `System` から取り出して、必要な関数にだけ渡す。
- 権限は値として渡せる。managed のレコードや class のフィールドにも入れられる。
- 段階 1 で実装する最小の API。これ以外は `docs/OPEN_QUESTIONS.md` に提案を書いてから足す。

  | 権限 | メソッド |
  | --- | --- |
  | `Log` | `info(msg: string): void`、`warn(msg: string): void`、`error(msg: string): void` |
  | `Clock` | `nowMs(): f64` |
  | `Random` | `nextF64(): f64`（0 以上 1 未満）、`nextU32(): u32` |
  | `Fs` | `readText(path: string): Result<string, IoError>`、`writeText(path: string, text: string): Result<null, IoError>` |
  | `Alloc` | メソッドなし。`Vec.create` などに渡すだけ |
  | `Ffi` | メソッドなし。C の関数の先頭の実引数に渡すだけ（§14.3） |
  | `Spawn` | `isolate<S, R>(f): Port<S, R>`（§15.2） |
  | `Net` | 予約 |

- `IoError` は `{ readonly code: string; readonly message: string }`。

### 7.2 大域の権限はない

使える大域の名前は §12 の一覧だけ。`console`、`Date`、`Math.random`、`fetch`、`process`、`globalThis`、`setTimeout` などは使えない（E5001。対応する権限を受け取る修正候補を付ける）。

### 7.3 決定的な関数

パラメータの型に、権限型、関数型、interface 型、`unknown`、`JsRef`、`Ptr`、`ConstPtr`、`CHandle`、`RingTx`、`RingRx`、`Port` のいずれも含まない関数を「決定的」と呼ぶ。ただし rt かつ unsafe の関数は、パラメータによらず決定的でない（権限なしで C の関数を呼べるため。§14.3）。リングとポートの結果はスレッドの間の順序で変わり、C の関数とポインタの先のメモリはこの文書の外で変わるので、これらを含む関数も決定的でない。コンパイラはこれを判定して問い合わせに答えられること。テストのキャッシュとミューテーションテストの対象選別に使う。

### 7.4 npm（`Js` 権限）

- `import { parse } from "npm:yaml"` で束縛される名前の型は `JsRef`（不透明）。
- `JsRef` に対してできる操作は、`Js` 権限のメソッドだけ。

  | メソッド | 型 |
  | --- | --- |
  | `js.call(f: JsRef, args: Array<JsRef>)` | `Result<JsRef, JsError>` |
  | `js.get(obj: JsRef, key: string)` | `Result<JsRef, JsError>` |
  | `js.await(v: JsRef)` | `Promise<Result<JsRef, JsError>>` |
  | `js.decode<T>(v: JsRef)` | `Result<T, CastError>`（`T` の条件は `cast` と同じ） |
  | `js.encode<T>(v: T)` | `JsRef` |
  | `js.callback<T>(f: (arg: Result<T, CastError>) => void)` | `JsRef` |

- `js.encode<T>` の `T` には `cast` と同じ条件が付く（関数、権限、`unknown`、`Map`、`Set`、class のインスタンスは E2002）。STS の関数を JS へ渡す方法は `js.callback` だけ。
- `js.callback<T>(f)` は、JS から呼べる関数を作る。JS が最初の引数を渡して呼ぶと、その値を `js.decode<T>` と同じ検査にかけ、結果の `Result<T, CastError>` を `f` に渡す。検査に失敗してもトラップせず、`f` が `err` を受け取る。`T` の条件は `cast` と同じ。`f` の戻り値は `void` で、JS 側には `undefined` を返す。2 つ目以降の引数は捨て、引数がなければ `undefined` が検査にかかる。`f` の中のトラップは回復できず、JS の呼び出し元をそのまま抜ける（`JsError` にならない）。
- JS 側で投げられた例外は、境界で `JsError` に変換される。
- `npm:` の import と `JsRef` は managed 層でのみ使える。

## 8. エラーとトラップ

- `Result<T, E>` は次の型の別名。`ok(v)` と `err(e)` で作る。

  ```ts
  type Result<T, E> =
    | { readonly kind: "ok"; readonly value: T }
    | { readonly kind: "err"; readonly error: E };
  ```

- `panic(msg: string): never` はトラップを起こす。
- **トラップは回復不能。** STS のコードからは捕捉できない。受け取るのはホスト（テストランナー、`main` の呼び出し元）だけ。
- トラップの種類。

  | コード | 原因 |
  | --- | --- |
  | T001 | 整数演算の結果が範囲外 |
  | T002 | 添字が範囲外 |
  | T003 | 数値変換の失敗。C の関数の `usize` の戻り値と `cfn` の関数の `usize` の引数が 2^32−1 を超えたときも含む（§14.2） |
  | T004 | `requires` の違反 |
  | T005 | `ensures` の違反 |
  | T006 | `panic` |
  | T007 | 0 による整数除算 |
  | T008 | `OwnedCell` の誤用 |
  | T009 | シフト量が範囲外 |
  | T010 | `invariant` の違反 |
| T011 | `Pool` のハンドルが無効（取り除いた後、別のプールのもの、範囲外） |
| T012 | `ArenaBuf` が無効（`reset` の前に取ったもの、別のアリーナのもの） |
| T013 | 1 つの呼び出しで、同じ根の `slice` の範囲が重なった（§5.5） |
| T014 | `Ring.create` の容量が不正（0、2 のべきでない、2^31 より大きい。§15.1） |
| T015 | null の `Ptr` への操作（`read`、`write`、`offset`、`slice`、`borrow`、`unbox`。§14.4） |

- 段階 3 で予約したトラップは全て実装済み。外部のスレッドのトラップは §15.4。

## 9. 契約とテスト

### 9.1 契約

- `requires(cond: boolean)`: 関数本体の先頭（指示子の直後）に 0 個以上書ける。参照できるのは引数だけ。
- `ensures((r: R) => boolean)`: `requires` の後に 0 個以上書ける。`r` は戻り値。式の中で参照できるのは `r` と Copy 型の引数だけ。この関数式は、strict / rt のクロージャ禁止の例外とする。
- `invariant(cond: boolean)`: ループ本体の先頭に書ける。
- 位置の違反は E6001、参照の違反は E6002。
- 契約は観測だけをする。契約の式の中の代入と、状態を変えうる組み込みメソッドの呼び出し（`push`、`Pool` の `insert`、`Ptr` の `write` など。`Port` の `send`、`recv`、`close` と `Spawn` の `isolate` を含む）は E6002（Q134、Q230）。確保する名前空間の関数のうち `Ptr.box` は E6002 で、`Vec.create`、`Pool.create`、`Arena.create`、`Ring.create`、`OwnedCell.create`、`CHandle.create` は契約の中で呼べる（Q230）。
- 契約の式は、その関数と同じ層の制限に従う。
- v0 では、契約は開発時も出力時も実行時に検査する。違反はトラップ（T004 / T005 / T010）。

### 9.2 テスト

- モジュール直下に `test("名前", (t: Test) => { ... })` と書く（E6003）。非同期なら `async (t: Test) => { ... }`。
- テストの本体は managed 層のコード。
- `Test` のメソッド。

  | メソッド | 挙動 |
  | --- | --- |
  | `t.ok(cond: boolean)` | 偽なら失敗 |
  | `t.eq<T>(a: T, b: T)` | 構造的に比較。`T` は managed の値か Copy 型（プリミティブ、レコード、union、`Array`、Copy の Struct） |
  | `t.eqSlice<T>(a: Ref<Slice<T>>, b: Ref<Slice<T>>)` | 長さと全要素を比較。`Vec` を移動せずに比べるためのもの |
  | `t.traps(code: string, f: () => void)` | `f` が指定のコードでトラップしなければ失敗。トラップを観測する唯一の手段 |

- **テストに本物の権限は渡されない。** 必要なら偽の権限を自分で作る: `FakeClock.create(0)`、`SeededRandom.create(42)`、`MemoryLog.create()`、`FakeFs.create()`、`TestAlloc.create()`。`Ffi` と `Spawn` の偽の権限はないので、テストから C の関数と isolate は使えない。
- テストは `sts test` のときだけ登録される。それ以外のビルドでは除去される。

## 10. 開発時の変換（JS バックエンド）

変換はファイル単位で行う。他のファイルについて必要なのは、export された宣言のシグネチャだけ（シグネチャはすべて注釈されているので、構文だけから取り出せる）。

1. 型注釈、`type`、`interface` を取り除く。
2. 整数型の `+`、`-`、`*`、単項 `-`、複合代入に範囲検査を入れる（T001）。
3. `f32` の演算結果を `Math.fround` で丸める。
4. `u32` のビット演算の結果を符号なしに正規化する。シフト量を検査する（T009）。
5. 変換関数、`wrap*`、`divTrunc`、`rem` をランタイム関数の呼び出しにする。
6. 添字アクセスに範囲検査を入れる（T002）。
7. `undefined` を返しうる組み込み（`Map.get`、`Array.find`、`pop` など）と `?.` の結果を `null` に正規化する。
8. 契約を検査コードにする。`ensures` はすべての `return` の経路で検査する。
9. 値の表現。
   - Struct: プレーンなオブジェクト。
   - `Vec<数値型>`: 対応する TypedArray を包んだもの。それ以外の `Vec`（要素は Copy 型）: §10.2 の固定のバイト配置で要素を並べた `Uint8Array` を包んだもの。C 側とはコピーせずにメモリを共有する。
   - `Slice`: 同じバッファへのビュー。
   - `Pool<T>`: 要素の型つき配列（または §10.2 の配置のバイト列）と世代の `Uint32Array` を包んだもの。容量は固定で伸びない。`Handle<T>`: プールの番号、世代、添字の 3 つの `u32` を持つプレーンなオブジェクト。
   - `Arena`: ホストの `ArrayBuffer`（`bytes` バイト）と、使用済みの位置と世代を包んだもの。領域の確保は `Arena.create` の 1 回だけ。`ArenaBuf<T>`: アリーナの番号、世代、先頭のバイト位置、長さの 4 つの `u32` を持つプレーンなオブジェクト。
   - 移動、借用、破棄: 何も生成しない（検査はコンパイル時に済んでいる）。
10. `test(...)` はテスト実行時だけ残す。
11. ソースマップを出す。トラップの位置はソース上の位置で報告する。

生成される JS が人間に読める必要はない。C 専用のプログラム（§14.7）は JS に変換して実行しない。

### 10.1 C バックエンドが一致させるべきこと（段階 2）

- 評価順は左から右（オペランド、実引数とも）。
- 浮動小数点は IEEE 754 の binary32 / binary64。積和の融合と fast-math は禁止。
- strict / rt で使える `Math` の関数は、両方で結果が正確に一致するものに限る: `abs`、`sqrt`、`floor`、`ceil`、`trunc`、`round`、`min`、`max`、`sign`、`fround`。`round` などは JS の定義に合わせること。`sin` や `exp` などの `Math` の関数は strict / rt では使えない。数学関数は §12 の `DetMath` を使う。
- トラップは、種類とソース上の位置が JS 側と一致すること。
- C 専用のプログラム（§14.7）には、この節の一致の要求を適用しない。

### 10.2 `Vec` の要素の配置（段階 2）

配置を持たない型（`null` だけの型と、それを含む型）は、strict / rt のコンテナの要素にできない（§3.3、Q229）。

数値型でない `Vec<T>` と `Slice<T>` の要素は、JS 側でも C 側でも次の配置でバイト列に並べる。要素 `i` は先頭から `i * size` バイトの位置にある。どちらの側もこの配置を通して読み書きするので、境界で値をコピーしない。

- バイト順はリトルエンディアン。C バックエンドはリトルエンディアンのホストだけを対象にする。
- 数値型: 同じ幅の整数または IEEE 754 の値。`usize` は 4 バイトの符号なし。大きさと整列は幅と同じ。`f32` の値は binary32 のまま格納されるので、読み戻すと同じ値になる。
- `boolean`: 1 バイト。偽は 0、真は 1。整列は 1。
- 文字列リテラル型と、文字列リテラルの union: 4 バイトの符号なし整数で、型のメンバの文字列を UTF-16 の符号単位の順に並べたときの添字。整列は 4。
- Struct とレコード（タグつき union のメンバ）: フィールドを `kind` を先頭に、残りを名前の UTF-16 の符号単位の順に並べる。各フィールドは自分の整列の倍数の位置に置き、間を詰め物で埋める。全体の整列はフィールドの整列の最大（フィールドがなければ 1）、大きさはそれの倍数に切り上げる。Struct のフィールドの Struct はその場に埋め込む。
- タグつき union: 各メンバをレコードとして配置する。ただし `kind` は union の全メンバの `kind` の値を並べたときの添字にする（先頭の 4 バイトがタグになる）。大きさは最大のメンバの大きさを、整列はメンバの整列の最大をとる。
- `T | null`: 1 バイトの有無（なしは 0、ありは 1）の後に、`T` の整列の位置に `T` を置く。なしのときの `T` の部分の中身は規定しない（観測できない）。
- `Handle<T>`: `u32` の 3 つ（プールの番号、世代、添字）をこの順に並べた 12 バイト。整列は 4。
- `ArenaBuf<T>`: `u32` の 4 つ（アリーナの番号、世代、先頭のバイト位置、長さ）をこの順に並べた 16 バイト。整列は 4。
- 詰め物と、使っていない部分のバイトは観測できない。
- 要素の読み出しはそのバイト列から新しい値（Struct とレコードは新しいプレーンなオブジェクト）を作る。Copy 型の値は不変なので、同一性は観測できない。書き込みは `Vec` のバイト列に直接書く。

  - 全層: `sin`、`cos`、`tan`、`atan`、`exp`、`log`、`log10`、`tanh`（どれも `(x: f64) => f64`）と、`atan2(y, x)`、`pow(x, y)`（どちらも `(f64, f64) => f64`）。`f64` 版だけを用意する。

## 14. C の関数と unsafe（段階 3）

この節と §15 のコードのうち、E1009、E4007、E4008、E7002 は実装済み（段階 3-1、検査器のみ。C への変換とヘッダ照合は後続の依頼）。E4009 は段階 3-2 で実装済み（`run` と `test` の実行の前。`check` は出さない）。E2009 は段階 3-3 で実装済み（P4 のヘッダ照合と、C バックエンドからの C の関数の呼び出し。`usize` の戻り値の T003 を含む）。T014 は段階 3-4 で実装済み（`Ring.create` の容量の検査。§15.1）。T015 は段階 3-5 で実装済み（null の `Ptr` の操作。§14.4）。`cfn` と中継の関数、終わりの旗、ほかのスレッドのトラップの報告（§14.6、§15.4）は段階 3-6 で実装済み。E2010、E2011 は段階 3-7 で実装済み（`spawn.isolate` と `Port`、送れる型の検査。§15.2）。段階 3 で予約したコードはこれで全て実装済み。

### 14.1 `c:` モジュール（Q192）

- C の関数はモジュール直下の `declare module "c:<パッケージ>:<ヘッダ>" { ... }` で宣言する。`<パッケージ>` は pkg-config のパッケージ名、`<ヘッダ>` は `#include <...>` に書くパスである。例: `declare module "c:sdl3:SDL3/SDL.h"`（Q202）。
  - 指定子は `c:` の後に、空でない 2 つの部分を 1 つの `:` で区切ったもの。部分には空白、制御文字、`:`、`<`、`>`、`"`、`\` を含めない。違反は E7002（Q224）。
  - 1 つのファイルに、同じ指定子の `declare module` は 1 つだけ書ける（E7002）。
- ブロックの中に書けるのは、本体のない `function` 宣言だけ。`export`、型引数、同じ名前の 2 回目の宣言は書けない。違反は E1000。パラメータと戻り値の型注釈は必須（E2006）。型は §14.2。
- 宣言した関数を「C の関数」と呼ぶ。名前がそのまま C の関数名になる。
- C の関数を使うには、同じファイルで `import { f } from "c:sdl3:SDL3/SDL.h"` と書く。指定子は `declare module` のものと文字単位で一致させる。同じファイルに一致する `declare module` がない場合と、宣言していない名前を import した場合は E7002。ほかのファイルからは import できない（Q202）。`c:` の指定子からの再 export は E7001。
- C の関数は呼び出し位置でしか使えない（ほかの位置は E4003）。呼べるのは unsafe の関数（§14.4）の中だけ（E4008）。
- 実引数の規則はふつうの関数の呼び出しと同じ。ただし、rt かつ unsafe の関数からの呼び出しでは先頭の `Ffi` の実引数を書かない（§14.3）。

### 14.2 型の対応とヘッダとの照合（Q193、Q204）

- C の関数の宣言では先頭のパラメータを `Ffi` 型にする（違反は E4007）。このパラメータは C には渡さない。
- 残りのパラメータに書ける型は、数値型、`boolean`、`Ptr<T>`、`ConstPtr<T>`（§14.4）。戻り値にはこれらと `void` を書ける。ほかの型（Struct、`Vec`、`Ref`、`Mut`、`T | null`、managed の型など）は E4007。構造体の値渡しはできない。
- C の型との対応（Q204）。C の関数の宣言と `cfn` の関数（§14.6）の型は、この表で 1 つの C の型に決まる。

  | STS | C |
  | --- | --- |
  | `i8`、`i16`、`i32` | `int8_t`、`int16_t`、`int32_t` |
  | `u8`、`u16`、`u32` | `uint8_t`、`uint16_t`、`uint32_t` |
  | `usize`（パラメータと戻り値） | `size_t` |
  | `f32`、`f64` | `float`、`double` |
  | `boolean` | `bool` |
  | `void`（戻り値） | `void` |
  | `Ptr<T>` | 指す先を下の規則で決めた `P *` |
  | `ConstPtr<T>` | 指す先を下の規則で決めた `const P *` |
  | `Ptr<(a: A, …) => R>` | `R`、`A`、… をこの表で対応させた関数へのポインタ |

  - 指す先 `P`: 数値型と `boolean` は上の表の型。`void` は `void`。`CType<"X">` は `X`。`Ptr<U>` と `ConstPtr<U>` はその対応（`P` はまたポインタになる）。それ以外の STS の型（`box` の中身。§14.4）は `void`。
  - 指す先の `usize` は C の関数の宣言と `cfn` の関数の型には書けない（E4007）。§10.2 の `usize`（4 バイト）と `size_t`（8 バイト）が違うため。
  - `usize` のパラメータは `size_t` へ 0 で広げて渡す。`usize` の戻り値と、C から `cfn` の関数に渡された `usize` の引数は、2^32−1 より大きければ T003（アンカーは呼び出し先の名前。`cfn` の関数ではそのパラメータの名前）。
  - 64 ビットの整数型（`int64_t`、`uint64_t`、`long` など）、`char`、C の構造体の値、可変長引数の関数は表せない（Q211）。そのような C の関数は宣言できない（照合で E2009 になる）。
- 照合: 生成する C は `<ヘッダ>` を `#include` し、`pkg-config --cflags` の結果でコンパイルし、`pkg-config --libs` の結果をリンクする。宣言 `function f(ffi: Ffi, a: A, …): R` ごとに、次の 1 行を `-std=gnu11` で `cc` にかける（`R_c`、`A_c` は上の表の C の型）。この行がエラーになるか、ヘッダがない、または pkg-config がパッケージを知らなければ E2009。
  ```c
  struct sts_probe { int x; };
  _Static_assert(__builtin_types_compatible_p(__typeof__(&f), R_c (*)(A_c, …)), "f");
  _Static_assert(!__builtin_types_compatible_p(__typeof__(&f), R_c (*)(A_c, …, struct sts_probe)), "f");
  ```
  - 1 行目は C の型の互換性による照合で、パラメータの数、各パラメータと戻り値の型、ポインタの指す先の型、`const`、関数ポインタの引数と戻り値の型、可変長引数かどうかを比べる。パラメータが 0 個なら、1 行目は `R_c (*)(void)`、2 行目は `R_c (*)(struct sts_probe)` にする。
  - 2 行目は、ヘッダの宣言がプロトタイプ（パラメータの型の並び）を持つことを確かめる。プロトタイプのない宣言（`int f();`）はどのプロトタイプとも互換になりうるので、1 行目だけでは数も型も比べられない。そのような宣言は 2 行目で E2009 になる。2 行目の `struct sts_probe` は生成する C でほかに使わない名前にする。
  - 対象の環境は Linux の LP64（x86-64 と arm64）で、`int` は `int32_t`、`bool` は `_Bool`、ポインタは 8 バイトである。この前提で、`int` を使う C の宣言は `i32` で照合を通る。
  - 照合は `check` でも行う。C の関数を使うプログラムの検査には `cc`、`pkg-config`、ヘッダが要る。
- 照合を通った C の関数は生成する C から直接呼ぶ（値の変換は `usize` の上の規則だけ）。

### 14.3 `Ffi` 権限と rt の例外（Q194）

- `Ffi` は §7.1 の権限型で、メソッドを持たない。`sys.ffi` で取り出す。
- strict かつ unsafe の関数から C の関数を呼ぶときは、先頭の実引数に `Ffi` の値を渡す。
- rt かつ unsafe の関数は権限なしで C の関数を呼べる（§7 の例外）。このとき先頭の `Ffi` の実引数は書かない。実引数の数は `Ffi` を除いた数でなければならない（E2002）（Q205）。
- この例外があっても権限の規則が保たれるように、rt かつ unsafe の関数を直接呼べるのは rt かつ unsafe の関数だけとする（§2 の表、E4001）。ほかの関数はその名前を `cfn`（§14.6）に渡すことしかできない（Q205）。`cfn` で得たポインタを C に渡すには C の関数を呼ぶ必要がある。そのため、権限なしの C の関数の呼び出しが起きるのは、`Ffi` を持つ関数が C に渡したコールバックの中（そこから呼ばれた関数を含む）だけになる。

### 14.4 `"use unsafe"`、`Ptr<T>`、`ConstPtr<T>`（Q198、Q204）

- `"use unsafe"` は層ではない。strict / rt の関数に重ねる修飾である。関数本体の先頭の指示子の並びに書く。層の指示子との順は問わない。その関数の層は関数かファイルの指示子で strict か rt になっていなければならない。ファイルの先頭、managed の関数、アロー関数と関数式に書いた場合と、2 回目に書いた場合は E1009。
- unsafe の関数の中にある契約の式（§9.1）も unsafe の中として扱う。
- unsafe は検査を緩めない。所有権、借用、層、型の規則はそのまま適用する。unsafe の関数の中でだけ、次のこと（「unsafe の操作」）ができる（ほかの場所では E4008）。
  1. 型に `Ptr`、`ConstPtr`、`CType` を書くこと（`CHandle` の型引数の `CType` を除く。§14.5）。型がこれらを含むローカル変数を推論させることも含む。
  2. C の関数を呼ぶこと。
  3. パラメータか戻り値の型が `Ptr` か `ConstPtr` を含む関数を呼ぶこと。`CHandle<T>` の中は数えない。`CHandle` だけを含む関数の呼び出しは unsafe の操作ではない（Q218）。
  4. `cfn`、`Ptr.box`、`Ptr` と `ConstPtr` のメンバ、`CHandle.create`、`CHandle` のメンバを使うこと。
- C の関数の宣言（§14.1）と、`Ptr<T>` の型引数の関数型（§14.6）にも、これらの型を書ける。
- シグネチャに `Ptr` と `ConstPtr` を含まない strict かつ unsafe の関数は、safe な関数からも呼べる。そのインターフェースを安全に保つのは、unsafe の関数の書き手の責任である。rt かつ unsafe の関数を呼べるのは rt かつ unsafe の関数だけである（§14.3）。
- **`Ptr<T>`** は C のポインタ、**`ConstPtr<T>`** は C の `const` 付きのポインタで、どちらも Copy 型。**`CType<"X">`** は C の型の名前 `X`（C の識別子）を表す型で、`Ptr`、`ConstPtr`、`CHandle` の型引数と、`cast` の型引数にだけ書ける（ほかは E4007）。値を持たず、`X` がヘッダの型の名前かどうかは §14.2 の照合で分かる。`X` は C の識別子（`[A-Za-z_][A-Za-z0-9_]*`）で、C の予約語（`int`、`long`、`char`、`unsigned`、`struct` など）と `bool` は書けない。違反は E4007（アンカーは文字列リテラル）。`typedef` の名前（`SDL_AudioStream`、`int64_t` など）を書く。`typedef` のない構造体のタグ（`struct S`）は表せない（Q211）。`CType` は指す先にしか現れないので、`CType<"int64_t">` のポインタを通しても 64 ビットの値は読み書きできない（`isNull` と `cast` だけ）。
  - `T` に書けるのは、数値型、`boolean`、`void`、`CType<"X">`、`Ptr<U>`、`ConstPtr<U>`、§3.3 の型（`Ref`、`Mut`、`Slice` を除く）、関数型（`Ptr` だけ。§14.6）。ほかの型は E4007 で、アンカーは型引数の先頭（Q216）。
  - `Ptr` と `ConstPtr` を書けるのは、パラメータ、戻り値、ローカル変数の型と、`Ptr` と `ConstPtr` の型引数と、`cast` の型引数だけ（Q219）。Struct のフィールド、`Vec` の要素、union のメンバ、`T | null` の `T`、ほかの型引数には書けない（E4008）。`Ptr.box` の型引数に `Ptr` と `ConstPtr` を書くことも、これに当たる（`Ptr.box<Ptr<i32>>` は E4008。`Ptr` は `box` でヒープに逃がさない。Q228）。
  - `Ptr<T>` の値は、`ConstPtr<T>` が要る位置（実引数、戻り値、注釈のある初期化）にそのまま書ける。逆はできない（E2002）。
  - 演算子（`===` を含む）は使えない。null の値を作る組み込みはない。値は C の関数の戻り値、`cfn`、`Ptr.box`、`offset`、`cast`、`CHandle` の `get` から得る。
- 操作。アンカーはどれもメンバ名。「Copy」の行は、`T` が数値型、`boolean`、`Ptr`、`ConstPtr`、Copy の Struct、Copy 型だけからなる union か `T | null` のときに使える。`T` が `void`、`CType`、関数型のときに使えるのは `isNull` と `cast`（関数型は `isNull` だけ）。それ以外の組み合わせは E2001。`ConstPtr<T>` で使えるのは、`isNull`、`read`、`offset`、`cast`（`offset` と `cast` の結果は `ConstPtr`）と、`Ref` のパラメータへの `slice` と `borrow` だけ（`Mut` のパラメータへは E3006）。

  | 操作 | `T` | 確保 | 意味 |
  | --- | --- | --- | --- |
  | `p.isNull(): boolean` | 任意 | なし | null なら `true` |
  | `p.read(): T` | Copy | なし | `p` の指すメモリから `T` を 1 つ読む |
  | `p.write(x: T): void` | Copy | なし | `p` の指すメモリに `x` を書く |
  | `p.offset(n: usize): Ptr<T>` | Copy | なし | `n` ×（`T` の大きさ）バイト先のポインタ |
  | `p.slice(n: usize)` | Copy | なし | 実引数の位置にだけ書ける（ほかは E3004）。`p` から `n` 要素の `Slice<T>` を、パラメータの型に応じて `Ref` か `Mut` で渡す |
  | `p.borrow()` | 所有型 | なし | 実引数の位置にだけ書ける（ほかは E3004）。`p` が指す `box` の中の値を、パラメータの型に応じて `Ref` か `Mut` で借用する（Q206） |
  | `p.cast<U>(): Ptr<U>` | 関数型以外 | なし | 同じアドレスを `Ptr<U>` として返す。`U` も関数型以外。`U` は指す先の位置で、上の `T` と同じ型を書ける。`void`（戻り値の型の外の `void` は E2002 だが、ここは例外。Q028、Q217）、`CType<"X">`、`Ptr<V>`、`ConstPtr<V>` も書ける（Q219）。`const` は外せない |
  | `Ptr.box<T>(alloc: Alloc, x: T): Ptr<T>` | 下の条件 | あり | `x` を移動して、C のヒープに新しく作った場所に入れる。確保に失敗したら T006 |
  | `p.unbox(): T` | 下の条件 | あり（解放） | `box` の場所から値を移動して取り出し、場所を解放する |

  - 読み書きの配置: 数値型、`boolean`、Struct、union、`T | null` は §10.2 の配置。`Ptr` と `ConstPtr` は C のポインタと同じ 8 バイトで、整列も 8。
  - `read`、`write`、`offset`、`slice`、`borrow`、`unbox` は、`p` が null なら T015。`isNull` と `cast` はトラップしない。
  - 借用の根: `p.slice(n)`、`p.borrow()`、`p.unbox()` の受け手に書けるのは、ローカル変数かパラメータ、またはそれに `offset` と `cast` を続けた式（`p.offset(2).cast<f32>()` など）だけで、ほかの式（呼び出しの結果、`h.get()` など）は E3008。§5.5 の排他性ではその先頭の変数 `p` を根とする（`g(p.slice(8), p.offset(2).slice(4))` で両方が `Mut` なら E3005）。`unbox` は受け手を `Mut` で使うものとして数える。そのため `g(p.borrow(), p.unbox())` は E3005。Q190 の実行時の重なりの検査（T013）は `p.slice` には当てない。同じ根の `p.slice` を 2 つ渡し、少なくとも一方が `Mut` なら E3005 のまま。
- **`box` に入れられる型**（Q209）: Copy 型、`RingTx<T>`、`RingRx<T>`、`CHandle<T>` と、フィールドがすべて box に入れられる型である Struct。`Vec<T>` と、`Vec` を含む型は入れられない（E4007。アンカーは `box` の型引数か、実引数の先頭）。`Pool<T>`、`Arena` と、それらを含む型も入れられない（Q210）。
  - `box` の場所の中身は C のメモリだけで表す。リングの端点は共有の領域の先頭のアドレス、容量、読み書きの位置の場所のアドレスとして入る。そのため、ほかのスレッドから `borrow` で使っても、JS のエンジンとホストには触れない。
  - `box` に入っているリングの共有の領域は、その `box` を `unbox` するまで解放されない。`unbox` で取り出した端点はふつうの値に戻る。
  - `unbox` しなかった `box` の場所と、その中のリングの共有の領域は、プロセスが終わるまで残る（破棄は観測できない）。`main` が終わった後に `unbox` されることはないので、解放されることもない。終わりの旗（§14.6）が立った後に新しく `f` が呼ばれることはないが、その時点ですでに動いていたコールバックは、最後まで場所と領域を使いうる。
- `box` と `unbox` は rt では使えない（E4004）。
- **未定義動作**: 次のことをしたときの結果は規定しない。コンパイラもランタイムも検出しない（検出するのは null の T015 だけ）。
  1. 有効でない場所（解放した場所、領域の外、`T` の大きさに足りない場所）を読み書きすること。領域の外を指すか、アドレスの計算が溢れる `offset`。
  2. `T` の整列に合わない場所を読み書きすること。
  3. `T` の値として正しくないバイトを読むこと（`boolean` の 0 と 1 以外、union のタグの範囲外など）。
  4. 同じ場所を指す 2 つの `Ptr` の値（`const q = p` のような複製を含む）から、同時に生きる借用を作り、その少なくとも一方が `Mut` であること。借用中の `box` の場所を、複製した `Ptr` から読み書きするか `unbox` すること。
  5. `box` で作っていない `Ptr` を `unbox` するか `borrow` すること。2 回目の `unbox`、`unbox` した後の使用。
  6. 同じ場所を複数のスレッドから同期なしに使い、少なくとも 1 つが書き込むこと。例外はリングの操作（§15.1）で、それも送り手を使うスレッドと受け手を使うスレッドがそれぞれ同時に 1 つだけのときに限る。同じ端点を 2 つのスレッドが同時に使うこと（`box` の `Ptr` の複製や、同時に動く同じコールバックを通したものを含む）は未定義動作である。
  7. `CType` で書いた型の中身（C の構造体の配置など）を、`cast` で読み書きするときに取り違えること。所有型が入った `box` の `Ptr` を `cast` して、その場所を `read` や `write` で読み書きすること。
  8. `ArenaBuf` の値を `read`、`cast`、C の関数を通して作ること（`view` は番号と世代しか調べないので、作った値で領域の外を読み書きしうる）。
  9. C の関数を、その関数の仕様に反して呼ぶこと（無効な引数、スレッドの制約など）。
  10. コールバックを呼んだスレッドのスタックの大きさが分からず（§14.6）、実際のスタックが足りなくなること。

### 14.5 `CHandle<T>`（Q203）

- `CHandle<T>` は `Ptr<T>` を 1 つ持つ所有型である。managed の関数を含む safe な関数にも書ける。移動、Struct のフィールド、`OwnedCell`、managed のローカル変数に置ける。`T` は `Ptr<T>` と同じ条件で、関数型と、`Ptr` か `ConstPtr` を含む型は書けない（E4008）。`T` には safe な関数でも `CType<"X">` を書ける（`CHandle<CType<"SDL_AudioStream">>` など）。
- 操作は unsafe の関数の中でだけ使える（E4008）。
  - `CHandle.create<T>(p: Ptr<T>): CHandle<T>`: 確保なし。
  - `h.get(): Ptr<T>`: 受け手は `Ref`。確保なし。
- 破棄では何も起きない（C の資源は解放されない）。資源を返すには、`CHandle` を値で受け取る unsafe の関数を書く。
- isolate には送れない（§15.2）。

### 14.6 `cfn` とコールバック（Q195、Q197）

- `cfn(f)` は unsafe の関数の中に書ける（E4008）。`f` は、モジュール直下（import を含む）のジェネリックでない rt の `function` 宣言の名前。unsafe かどうかは問わない。名前でない式は E4003、rt でない関数の名前は E4001（アンカーは `f`）。`f` のパラメータと戻り値の型は §14.2 の型で、`Ffi` と関数型パラメータ（§3.3）は含めない（違反は E4007、アンカーは `f`）。
- rt かつ unsafe の関数の名前は、§3.3 の関数型パラメータ（Q189）への実引数にも書けない（E4001）。書けるのは `cfn` の実引数と、rt かつ unsafe の関数からの直接の呼び出しだけ（§14.3）。
- `cfn(f)` の型は `Ptr<F>` で、`F` は `f` の関数型である（例: `Ptr<(user: Ptr<State>, stream: Ptr<CType<"SDL_AudioStream">>, n: i32, total: i32) => void>`）。関数型はここと C の関数の宣言の中でだけ `Ptr` の型引数に書ける（§3.3 の関数型パラメータの位置の制限の例外）。パラメータの名前は比べず、型は完全に一致しなければならない（E2002）。C の側の関数ポインタの型とは §14.2 の照合で比べる。
- コンパイラは `cfn` に渡された関数ごとに、§14.2 の表の C の型を持つ中継の関数を作る。C はこれを、どのスレッドから、いつ呼んでもよい。同じ中継の関数を同時に呼んでもよい。そのときの各呼び出しは独立に動き、共有する状態の扱いは §14.4 の未定義動作の 6 に従う。
- **終わりの旗**: プログラムに 1 つの旗を置く。どこかのスレッドでトラップが起きたとき（§15.4）と、`main` が終わったときに、アトミックに立てる。
- 中継の関数が呼ばれたときの動作。
  1. 終わりの旗が立っていれば、`f` を呼ばず、すぐに戻り値の型の 0 の値を返す。数値は 0、`boolean` は `false`、`Ptr` は null。`void` なら何も返さない。
  2. それ以外なら、引数を STS の値にして（§14.2 の `usize` の規則を含む）`f` を呼び、`f` の戻り値を返す。
  3. `f`（そこから呼んだ関数を含む）がトラップしたら、1 と同じ 0 の値を返す。`f` がすでにした書き込みと C の関数の呼び出しは取り消さない。トラップは §15.4 のとおり扱う（旗を立てる）。
  - 旗が立った時点ですでに `f` を実行している呼び出しは止めない。その呼び出しは最後まで動き、トラップすればそのトラップは捨てられる。
- コールバックが SDL3 のように出力を C の関数で渡す形なら、旗が立った後の呼び出しは何も渡さない。そのため出力は無音になる。
- 再帰の深さの上限とスタックの下限（T006、Q035、Q182）は、コールバックを呼んだスレッドごとに数える。スタックの下限はそのスレッドのスタックの範囲を OS から得て計算する。得られなければ深さの上限だけを使う（§14.4 の未定義動作の 10）。

### 14.7 C 専用のプログラム（Q196）

- プログラムのどれかのファイルに、`c:` の `declare module` か、unsafe の操作（§14.4 の 1〜4）があれば、そのプログラムを「C 専用」と呼ぶ。unsafe の操作を含まない `"use unsafe"` の関数だけでは C 専用にならない。
- C 専用のプログラムは C バックエンドでだけ実行する。`run` と `test` を `--backend=js`（既定）か `--backend=both` で実行すると、何も実行せずに E4009 で止まる。アンカーはプログラムのファイルをパスの順に見て最初に現れる `c:` の指定子か、unsafe の操作（そのアンカーは E4008 と同じ）。`check` は E4009 を出さない。
- §0.2 の例外: C 専用のプログラムには基準になる JS の実行がない。STS で書いた部分の意味はこの文書の規則で決まる。C の関数の呼び出しの効果はその C の関数で決まる。§10.1 の一致の要求は適用しない（比べる相手がない）。
- 適合テスト: C 専用のケースには `// stage: N` の次の行に `// backend: c` を書く。ハーネスはそのケースを C バックエンドだけで実行し、JS とは比べない。受理と拒否のケースでも、§14.2 の照合のために C の道具を使う。

## 15. 並行性（段階 3）

### 15.1 リングバッファ（Q199）

- 型: `RingTx<T>`（送り手）と `RingRx<T>`（受け手）。どちらも所有型。`T` は Copy 型で、条件と違反のコードは `Vec<T>` と同じ。`ArenaBuf<T>` と、それを含む型は要素にできない（E2002。端点は isolate に送れるため。Q210）。`RingPair<T>` は組み込みの Struct で（タプルがないため。Q199）、`Struct<{ tx: RingTx<T>; rx: RingRx<T> }>` と同じ。`const { tx, rx } = Ring.create<T>(alloc, 64)` のように分解して使う。

  | 操作 | 受け手の借用 | 確保 | 備考 |
  | --- | --- | --- | --- |
  | `Ring.create<T>(alloc: Alloc, capacity: usize): RingPair<T>` | — | あり | `capacity` が 0、2 のべきでない、または 2^31 より大きいなら T014（アンカーは `create`）。確保の失敗は `Vec.create` と同じ |
  | `tx.push(x: T): boolean` | Mut | なし | 入っている数が `capacity` より少なければ、`x` を末尾に足して `true`。満杯なら何もせず `false`（`x` は捨てる） |
  | `rx.pop(): T \| null` | Mut | なし | 先頭の値を取り除いて返す。空なら `null` |

- 全層で使える（`Ring.create` は rt では E4004）。managed でも §5.6 の規則に従い、呼び出しをまたいで持つには `OwnedCell` を使う。Struct のフィールドにも置ける。
- 送り手と受け手はそれぞれ 1 つしかない。コピーできず、`push` と `pop` には `Mut` の借用が要るので、同時に push する者と pop する者はそれぞれ 1 人に限られる。
- 送り手と受け手が別のスレッドにあっても、次のことが成り立つ。
  1. `pop` が返す値は、`push` が `true` を返した値である。`push` した順に、ちょうど 1 回ずつ返る。値は `push` したときの値のまま（§10.2 の配置でコピーする）。
  2. `push` は、自分から見えた受け手の位置で満杯なら `false` を返す。`pop` は、自分から見えた送り手の位置で空なら `null` を返す。相手の位置の見え方は古いことがある。そのため、相手がすでに取り出した（または足した）後でも `false`（または `null`）になりうる。逆に、満杯なのに上書きすること、足されていない値を返すことはない。
  3. `push` が `true` を返した値は、有限の時間の後に受け手から見えるようになり、その後の `pop` で得られる。その時間は決めない。
  4. `push` と `pop` はロックを取らず、待たず、確保せず、ホストを呼ばない。
  5. 送り手と受け手の一方が破棄されても、もう一方はそのまま使える。
- 1 つのスレッドの中では、結果は `push` と `pop` の列だけで決まる。スレッドの間で決まらないのは、ある `push` がある `pop` より先に見えるかどうかだけである。
- 表現（両方のバックエンド）: 領域は JS の SharedArrayBuffer に置き、要素は §10.2 の配置で並べる。読み書きの位置は、JS は `Atomics`、C は C11 のアトミック操作で、取得と解放の順序を付けて読み書きする。
- 送り手と受け手は、isolate に送れる（§15.2）。`Ptr.box` で C に渡すこともできる（§14.4、Q209）。

### 15.2 isolate（Q200）

- `Spawn` は §7.1 の権限型で、`sys.spawn` で取り出す。メソッドは `spawn.isolate<S, R>(f): Port<S, R>` だけで、managed でだけ使える（strict / rt では `Port` が E4002）。
- `f` は、モジュール直下（import を含む）のジェネリックでない managed の `function` 宣言の名前で、シグネチャは `(port: Port<R, S>): void` か `(port: Port<R, S>): Promise<void>`。ほかの式とシグネチャは E2011（アンカーは実引数の先頭）。
- `spawn.isolate` は新しい isolate（JS の Worker）を起こし、そこでプログラムのモジュールを読み込み、`f(port)` を呼ぶ。`f` の開始を待たずに戻る。isolate はほかの isolate と managed の値を共有しない。v0 では isolate に権限を渡す方法はない。C バックエンドでは、isolate も同じ C のコードを使う（D111）。
- isolate は、`f` が戻ったとき（`Promise` なら解決したとき）に終わる。そのとき isolate の側のポートは閉じる。
- `Port<S, R>` は managed の値（所有型ではない）で、`S` を送り `R` を受け取る。

  | メソッド | 挙動 |
  | --- | --- |
  | `port.send(x: S): void` | `x` を相手に送る。`S` が所有型を含むなら `x` は移動する（§5.2 の値渡し）。ポートが閉じていれば `x` を捨てる |
  | `port.recv(): Promise<R \| null>` | 次のメッセージで解決する。相手の側が閉じていて、届いたメッセージが残っていなければ `null`。複数の `recv` は呼んだ順に解決する |
  | `port.close(): void` | （Q207）両方向を閉じる。2 回目以降は何もしない。閉じた後の `send` は捨てる。相手の `recv` は、届いた分を受け取った後で `null` になる |

- 1 つの方向のメッセージは送った順に届く。いつ届くかは決めない。
- **送れる型**: `Port<S, R>` の `S` と `R` は次の型に限る。`Port` の型を書いたすべての位置で検査する（違反は E2010、アンカーはその型引数の先頭）。
  1. 数値型、`boolean`、`null`、`string`、文字列リテラル型とその union。
  2. 全フィールドが `readonly` で、各フィールドの型が送れる型であるレコード。そのようなレコードだけからなるタグつき union。`T` が送れる型である `T | null`。
  3. Copy の Struct。
  4. 所有型のうち、`CHandle` を含まないもの（`Vec<T>`、非 Copy の Struct、`RingTx<T>`、`RingRx<T>`）。`Pool<T>`、`Arena`、`ArenaBuf<T>` と、それらを含む型は送れない（アリーナの番号は isolate ごとに 1 から振るので、別の isolate の `ArenaBuf` が `view` の番号と世代の検査を通りうる）。`Handle<T>` は Copy 型で、無効なハンドルは T011 で止まるので送れる（Q210）。
  - `Array`、`ReadonlyArray`、`Map`、`Set`、class、関数、権限、`unknown`、`JsRef`、`Promise`、`Port`、`OwnedCell`、`CHandle` と、これらを含む型は送れない。
- 1〜3 の値はコピーして渡す（深く不変なので、コピーか共有かは観測できない）。所有型の値は移動する。`Vec` の領域は相手の isolate に移る（ArrayBuffer の移譲）。リングの端点は同じ共有の領域を指したまま移る。
- `R` が所有型を含むとき、`port.recv()` は `await` のオペランドとしてだけ書ける（§5.6 の E3007 の例外。ほかの位置は E3007）。結果の `R | null` は `const` のローカル変数に受け、`x !== null` で絞り込んでから、変数全体を移動して使う（§3.3 の `T | null` の Copy の条件の例外）（Q207）。
- `main` が終わると（同期に戻るか、返した `Promise` が解決すると）、まだ動いている isolate は止められ、届いていないメッセージは捨てられる（Q207）。
- isolate の中のトラップはその isolate をそこで止め、§15.4 のとおり managed の側に届く。

### 15.3 スレッド（Q201）

- STS にはスレッドを起こす機能がない。`Spawn` が起こすのは isolate だけである。
- managed の外のスレッドで rt の関数が動くのは、C のライブラリが自分のスレッドから `cfn` のコールバックを呼ぶときだけである。ROADMAP の「rt 層だけが動くスレッド」はこれを指す。
- strict と rt の関数は呼び出し元のスレッド（managed のスレッド、isolate のスレッド、またはコールバックを呼んだ C のスレッド）で動く。

### 15.4 ほかのスレッドで起きたトラップ（Q197、Q208）

- 中継の関数の中（§14.6）と isolate の中（§15.2）で起きたトラップを「ほかのスレッドのトラップ」と呼ぶ。
- プログラムが報告するトラップは 1 つだけである。どのスレッドで起きたトラップも、§14.6 の終わりの旗を立てようとする。旗を最初に立てたトラップを報告し、旗がすでに立っていたトラップは捨てる。`main` のスレッドのトラップとほかのスレッドのトラップが競ったときも、この順で決める。
- 報告するほかのスレッドのトラップは次のうち最も早い時点で、`main` を動かしているスレッドで起きる。報告するコードと位置は、ほかのスレッドで起きたときのもの。
  1. 中継の関数のトラップに限り: managed から strict / rt の関数への呼び出しが managed に戻る直前。
  2. そのスレッドが次のタスク（`await` の再開、メッセージの受け取りなど）を始める前。
  3. `main` が終わったとき。
- 起きたトラップは、ほかのトラップと同じくホストが受け取り、プログラムはそこで終わる。
- `main` が終わった後に起きたほかのスレッドのトラップは観測されない（旗はすでに立っている）。
