# 診断とトラップのコード

「コード」と「意味」の列は `docs/SPEC.md` §13 の写し。意味は変えない。コードの追加は連番で行い、追加したらこの表と SPEC と `packages/compiler/src/explain.ts` のすべてに書く（`szigyr explain <code>` / MCP `szigyr_explain` で参照可能）。

## 位置の数え方とフェーズ

- 行・列は 1 始まり。列は UTF-16 符号単位で数え、タブも 1 と数える。BOM は数えない（Q001）。
- `range.start` は下の表の「アンカー」が指すノードかトークンの先頭で、前置トリビアは除く（`node.getStart()`）。`range.end` は排他的（Q001）。
- 表にない形には Q002 の一般則を適用する。
- `szigyr check --json` は各診断を `{"kind":"diagnostic", ...}` として出力し、可能な箇所には機械可読な `data` と `fixes` を添付する。
- コンパイラは P1（構文）→ P2（型・層・権限）→ P3（所有・借用・`using`）→ P4（C ヘッダ照合）の順に検査する。`szigyr check` は回復可能なエラーの後ろも検査を継続し（`<error>` 連鎖は抑制）、1 回の実行で複数フェーズの問題を報告する。
- 拒否ケースのファイル（`conformance/reject/`）は既定で「最初の診断」（`(line, col, code)` 順の先頭）を比較する（単一違反を推奨）。
- 「Q」列の項目は `docs/OPEN_QUESTIONS.md` の整理番号。
