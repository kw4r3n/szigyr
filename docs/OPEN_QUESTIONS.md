# 仕様の穴（OPEN QUESTIONS）

`docs/SPEC.md` の穴、矛盾、あいまいな点の記録。実装は「既定案」に従う。適合テストで既定案に依存する箇所には `// open-question: Q012` の形で印を付ける。

- ID は安定している。番号は振り直さない。解決した項目も消さず、「状況」の末尾に「解決: …（SPEC §x を改訂）」と追記する。
- 既定案は、SPEC が改訂されるまでの暫定の規範とする。SPEC と既定案が食い違ったら SPEC が正しい。
- 「SPEC 修正候補」と書いた項目は、SPEC 自体の矛盾か欠落であり、SPEC の改訂で決着させるべきもの。
- 行:列の例は、とくに断らない限り、SPEC 付録のコード片の 1 行目を 1 行目として数える。適合テストのファイルでは先頭に `// expect:` 行が入るので、行番号が 1 増える。

## A. 診断とその位置

### Q001 行・列の数え方
- 関連: §11
- 状況: SPEC が決めているのは「1 始まり」だけ。§11 の JSON 例では `buf`（3 文字）が col 9 〜 12 なので、`end` は終端の次の位置（排他的）だと読める。
- 選択肢: 列を (a) UTF-16 符号単位、(b) Unicode コードポイント、(c) バイトで数える。
- 既定案:
  - 行も列も 1 始まり。列は UTF-16 符号単位で数える（`typescript` の `getLineAndCharacterOfPosition` の character + 1）。
  - タブも 1 単位と数える。
  - 改行は TS のスキャナに従い、`\n`、`\r\n`（2 文字で 1 つの改行）、`\r`、U+2028、U+2029 を改行とみなす。
  - 先頭の BOM は数えない（BOM の直後が 1:1）。
  - `range.end` は排他的とする。ハーネスが比べるのは `range.start` だけ。
  - トラップの位置も同じ数え方にする。

### Q002 アンカー（`range.start`）の一般則
- 関連: §11、§8、§10.1
- 状況: 診断がどの構文ノードを指すか、SPEC に規定がない。トラップについては §10.1 が「JS と C で位置が一致すること」を求めているので、両バックエンドが同じ値を計算でき、同じ行で入れ子になった演算どうしを区別できる位置でなければならない。
- 選択肢: (a) 違反ノードの先頭、(b) 違反を特徴づけるトークン、(c) 文の先頭。
- 既定案: コードごとの詳細は `docs/DIAGNOSTICS.md` の表に従う。表にない場合は次の一般則を使う。位置はいずれも前置トリビア（空白・コメント）を除いた位置（`node.getStart()`）。
  1. 二項演算子とそれに類する構文（`==`、`!=`、`as`、`satisfies`、後置 `!`、`in`、`instanceof`、カンマ演算子、算術・ビット・比較・複合代入）は、演算子トークンを指す。
  2. 呼び出しは「呼び出し先の名前トークン」を指す。`f(x)` なら `f`、`a.b(x)` なら `b`、`Vec.create<T>(...)` なら `create`。
  3. 添字アクセス `a[i]` は添字の式 `i` の先頭を指す。
  4. 宣言の違反（注釈がない、省略可能など）は、宣言された名前の識別子を指す。
  5. 値の違反（型の不一致、格納できない値など）は、問題の値を生む式の先頭を指す。
  6. 構文の違反（禁止された文や型）は、その構文のノードの先頭（キーワードがあればキーワード）を指す。

### Q003 「最初の診断」の決め方
- 関連: §11、ROADMAP 段階 0
- 状況: 拒否ケースは「最初の診断」のコードと位置を比べる。しかし、診断の順序も、エラーのあとで検査を続けるかどうかも決まっていない。
- 選択肢: (a) 出力順、(b) 位置順、(c) フェーズ順のあと位置順。
- 既定案:
  - コンパイラは次のフェーズを順に実行し、エラーが出たフェーズで止まる。
    - P1: 構文・許可リスト。E1xxx、E5002、E6001、E6003、E7001。
    - P2: 名前・型・層・権限・契約の参照。E2xxx、E4xxx、E5001、E6002。
    - P3: 所有権・借用。E3xxx。
  - ハーネスは、出力順に関係なく、全診断を (line, col, code の文字列順) でソートし、その先頭を「最初の診断」とする。止まったフェーズより後のフェーズの診断は、そもそも出ない。
  - 拒否ケースの 1 ファイルには違反をちょうど 1 つだけ書く。これはテスト作成者への規約である。
  - フェーズ内のカスケード（エラー型からの二次エラー）は抑止する。エラー型を含む式からは新しい診断を出さない。

### Q004 E1000 と個別コードの振り分け
- 関連: §3.2（禁止する型機能）、§4、§11、§13
- 状況: §3.2 は「E1004 〜、なければ E1000」と言うだけで、個別コードがあるのは一部しかない。`object` や `Partial` などは、§12 の型一覧にない名前でもあるため、E2000 とも読める。
- 選択肢: (a) §3.2 に列挙された機能は E1000 とする、(b) 名前の形をとるものは E2000 とする。
- 既定案: 個別コードがあればそれを使う。§3.2 と §4 に列挙された機能で個別コードのないものは、名前の形をとるものでも E1000 にする。対応は次のとおり（閉じたリスト）。
  - 個別コード: `any` → E1004。`as`（`as const` を除く。Q026）→ E1005。後置 `!` → E1006。`throw`、`try`（`catch` / `finally` を含む）→ E1007。省略可能なプロパティと引数（`?`）、既定引数 → E1008（Q005）。`var` → E1001。`==`、`!=` → E1002。
  - E1000: `object`、`Function`、型としての `{}`、`symbol`、`enum`、`namespace` / `module`、`satisfies`、型述語 `x is T`、`asserts`、関数オーバーロード、宣言のマージ（同名の宣言が 2 つ）、`declare`、conditional 型、mapped 型、template literal 型、indexed access 型、`keyof`、型の `typeof`、`unique symbol`、残余引数 `...x`、タプル型、`T[]` と `readonly T[]`、数値リテラル型、`true` / `false` 型、配列の分割代入、ラベル、`with`、`eval`、`delete`、`in`、`instanceof`、値の `typeof`、`void` 演算子、カンマ演算子、`arguments`、ジェネレータ（`function*`、`yield`）、`for...in`、`++`、`--`、単項 `+`、正規表現リテラル、BigInt リテラル、タグつきテンプレート、class の `extends`・getter / setter・index signature・`abstract`・`#private`・パラメータプロパティ、interface の `extends` とプロパティシグネチャ、既定の型引数、`T extends I` 以外の制約、`using`、デコレータ、`import.meta`、`new.target`、クラス外の `this`、`let` / `for (let x of …)` の分割代入、ネストした分割代入パターン、計算プロパティ名と文字列リテラルのプロパティ名、`x?.[i]`、`f?.()`、`"use strict"` などの未知の指示子、`"use unsafe"`、アロー関数内の指示子。
  - 追記（ジェネレータのアンカー）: `function*` 宣言と `function*` 式は `function` キーワードの先頭を指す。ジェネレータのメソッド `*m()` は `*` を指す。ジェネレータの外にある `yield` は `yield` キーワードを指す。ジェネレータの中の `yield` はジェネレータ自体の E1000 だけを出す（Q003 のカスケード抑止）。
  - ユーティリティ型として E1000 にする名前: `Partial`、`Required`、`Readonly`、`Record`、`Pick`、`Omit`、`Exclude`、`Extract`、`NonNullable`、`Parameters`、`ConstructorParameters`、`ReturnType`、`InstanceType`、`ThisParameterType`、`OmitThisParameter`、`ThisType`、`Awaited`、`Uppercase`、`Lowercase`、`Capitalize`、`Uncapitalize`、`NoInfer`。これ以外の未知の型名は E2000。
  - `new Function`、`Proxy`、`Reflect`、`Symbol` は名前の問題として E2000 にする（§4 に列挙されているが、大域名なので）。

### Q005 既定引数のコード（SPEC 修正候補）
- 関連: §3.2、§11、§13
- 状況: §11 は既定引数を E1008 に割り当てている。一方 §13 は「既定引数」を予約に入れ、「E1000 か E2000 で拒否」と書く。
- 選択肢: (a) E1008、(b) E1000。
- 既定案: E1008。アンカーは引数名。§13 の記述は「将来導入の予定がある」という意味に読み替える。

### Q006 E2000 と E5001 の境界
- 関連: §7.2、§11、§12
- 状況: どの名前が「大域の権限」（E5001）で、どの名前が単なる未知の名前（E2000）かが列挙されていない。
- 既定案:
  - E5001 は、名前解決に失敗した識別子が次の閉じたリストに入っているときに出す: `console`、`Date`、`fetch`、`process`、`globalThis`、`window`、`self`、`global`、`setTimeout`、`setInterval`、`clearTimeout`、`clearInterval`、`setImmediate`、`queueMicrotask`、`performance`、`crypto`、`navigator`、`document`、`localStorage`、`sessionStorage`、`XMLHttpRequest`、`WebSocket`、`Worker`、`Deno`、`Bun`、`require`（ただし `require(...)` の呼び出しは Q009 の E7001 が優先する）。
  - メンバの形で E5001 にするもの: `Math.random`。アンカーはメンバ名 `random`。
  - それ以外の、解決できない識別子（打ち間違いを含む）は E2000。
  - ローカルの宣言がこれらの名前を隠している場合は、そのローカルを参照する（例: 引数名 `console`）。

### Q007 E2001 と E2002 の境界
- 関連: §11、§12
- 状況: E2001 は「仕様にない組み込みメンバ」。ユーザー定義型にないメンバへのアクセスのコードは決まっていない。
- 既定案:
  - 組み込み型（`string`、`Array`、`ReadonlyArray`、`Map`、`Set`、`Promise`、`Vec`、`Slice`、`OwnedCell`、権限型、`Test`、名前空間オブジェクト）の、許可リストにないメンバ → E2001。アンカーはメンバ名。
  - レコード、class、interface、Struct にないメンバ → E2002。アンカーはメンバ名。
  - 添字アクセスは `Array`、`ReadonlyArray`、`Vec`、`Slice` だけに許す。`string`、`Map` への添字は E2001、レコードや class への添字（`p["x"]`）は E2002。アンカーは添字の式。

### Q008 演算子の型エラーのコード
- 関連: §3.1、§11
- 状況: E2003（数値型の混在）、E2007（整数型の `/`）以外の、演算子と型の組み合わせのエラーにはコードがない。
- 既定案（アンカーはすべて演算子トークン）:
  - 両辺がともに数値型で、型が違う二項演算・比較・複合代入 → E2003。
  - 両辺が整数型の `/` と `/=` → E2007。
  - 整数型の `%`、`**`、`%=`、`**=` → E2002（E2007 の意味は広げない）。代替案は専用コードを新設すること。
  - ビット演算の型違反（`i32` / `u32` 以外、`>>` に `u32`、`>>>` に `i32`）→ E2002。
  - 単項 `-` を符号なし整数に使う → E2002。ただし負のリテラルは Q015 に従う。
  - 数値型と非数値型の組み合わせ（`"a" + 1` など）→ E2002。
  - 代入、実引数、`return` での数値型の不一致（`const x: f64 = i` など）は、演算ではないので E2002。

### Q009 E1003 と E7001、import / export の形
- 関連: §1、§7.4、§11
- 既定案:
  - default export（`export default …`）と `export *`（`export * as ns` を含む）→ E1003。アンカーは `export` キーワード。
  - 次は E7001。アンカーは文の先頭キーワード、`require` はその識別子、動的 import は `import` キーワード。
    - 動的 `import()`、`require(...)`、`import x from`（default import）、`import * as ns`、副作用だけの `import "x"`、`import x = require()`、`export =`。
    - 拡張子 `.ts` のない相対 import、`.ts` 以外の拡張子、`./` / `../` でも `npm:` でもない指定子。
    - re-export（`export { a } from "./a.ts"`）、`import type` と `export type { … }`（型も通常の名前付き import で取り込む）。
    - 存在しない名前、または export されていない名前の import。
  - 追記（同じ文で 2 つが競合する場合）: 指定子が不正（拡張子なし、未知の形式）なら、そのモジュールは解決しない。E7001 は指定子の文字列リテラルに 1 つだけ出し、名前の存在は検査しない。指定子が正しくてファイルが存在しないときも、指定子に 1 つだけ出す。名前ごとの E7001 は、モジュールが解決できたときだけ出す。
  - `import { a as b }` の別名は許す。
  - `npm:` の import はどのファイルにも書ける。束縛された `JsRef` を strict / rt の関数で使うと E4002 になる。

### Q010 組み込み名と同名の宣言（SPEC 修正候補）
- 関連: §1、§12
- 状況: §1 は「同名の宣言は禁止」と言うが、コードを割り当てていない。
- 選択肢: (a) E1000、(b) 専用コードを新設。
- 既定案: E1000。アンカーは宣言された名前。対象は §12 の大域名（型名、関数名、`Math`、`Number`、`JSON`、`String`、`Promise`、`Vec`、`OwnedCell`、偽の権限の名前）で、型・値・引数・ローカル・import の別名のいずれの宣言にも適用する。メンバ名（`length` など）は対象外。

### Q011 §13 の予約を E1000 と E2000 のどちらにするか
- 関連: §7.1、§13
- 状況: §13 は「E1000 か E2000」と言うだけ。また `Ffi`、`Spawn` は §7.1 の権限型として §12 の型一覧に入る一方で、予約でもある。
- 既定案:
  - 名前の形をとるもの → E2000（アンカーは名前）。`i64`、`u64`、`bigint`、`FixedArray`、`Rc`、`Weak`、`Ptr`、`Arena`、`Pool`、`Ffi`、`Spawn`、`Net`、`forAll`、`decreases`、`extern`。
  - 構文の形をとるもの → E1000。`using`、`"use unsafe"`、BigInt リテラル、`declare`。
  - `sys.net`、`sys.ffi`、`sys.spawn` → E2001。

### Q012 クロージャによる捕捉で、3 つのコードが重なる
- 関連: §2、§5.5、§5.6、§11
- 状況: E3004 の 4 項目め（借用の捕捉）、E3007（所有型の捕捉）、E4003（strict / rt のクロージャ）が重なりうる。
- 既定案:
  - strict / rt: アロー関数と関数式は、捕捉の有無に関係なく E4003（`ensures` の引数は除く）。アンカーは関数式の先頭。E3004 と E3007 は出さない。
  - managed: `Ref` / `Mut` の値の捕捉 → E3004、所有型の値の捕捉 → E3007。アンカーは、関数本体の中で捕捉された変数を最初に参照している識別子。
  - テスト本体（managed）の中の `t.traps("T002", () => { … })` も同じ規則に従う。外側の `Vec` を捕捉すると E3007 になるので、`Vec` はクロージャの中で作る（Q047）。

### Q013 `v.slice(a, b)` を実引数以外に書く
- 関連: §3.3、§5.5
- 状況: `slice` は「実引数の位置でのみ書ける」とあるが、違反のコードがない。メソッドの受け手の位置で使えるかもはっきりしない。
- 既定案:
  - 受け手の位置（`v.slice(0, 2).fill(x)`）は許す。§5.5 で受け手は実引数の 1 つとして数えるため。
  - それ以外の位置（ローカル変数への初期化、`return`、フィールドへの格納など）→ E3004。アンカーはメンバ名 `slice`。
  - managed の `Array.prototype.slice` は別物で、新しい `Array` を返す。どこにでも書ける。

## B. 型

### Q014 数値リテラルの文脈型付け
- 関連: §3.1、§11
- 状況: 「文脈の型」の伝わり方と、文脈がない場合の扱いの細部が決まっていない。
- 既定案:
  - 文脈になるもの: 変数の型注釈、代入先の型、二項演算と比較のもう一方のオペランド、仮引数の型（推論済みの型引数を含む）、`return` に対する関数の戻り値型、配列リテラルの要素型、レコードと Struct のフィールド型、添字（`usize`）、三項演算子に対する外側の文脈。
  - 文脈は後ろから前へは伝わらない。ローカル変数の型は宣言の時点で決まり、後の使い方からは推論しない。
    - `let i = 0` は `f64`。そのあとの `i < v.length` は E2003（§11 の fix `let i: usize = 0` を付ける）。
    - `const x = 1` も `f64`。`x === n`（`n: usize`）は E2003。
  - 両辺がリテラルだけでできた式（`1 + 2`）は、外側の文脈の型を受け取る。`x + (1 + 2)` で `x: i32` なら、内側も `i32` になる。文脈がまったくなければ `f64`。
  - ジェネリック呼び出しでは、まずリテラルでない実引数から型引数を推論し、そのあとでリテラルの実引数に文脈を与える。`t.eq(a[0], 6)` で `a: Vec<f32>` なら `T = f32` で、`6` は `f32`。全部がリテラルなら `f64`。
  - 追記（借用の仮引数）: 仮引数の型が `Ref<P>` / `Mut<P>` のとき、実引数の文脈型は `P`（`Ref<Slice<T>>` なら `Slice<T>`）。この文脈で型は決まるが、実引数が場所式でなければ E3008 になる。たとえば、所有型の Struct `S` について、`Ref<S>` の仮引数に Struct リテラルを渡すと、リテラルは `S` として型が付いたうえで E3008 になる（E2002 や E2006 にはならない）。
  - 追記（`??` と `?.`）: `x ?? e` で `x: T | null` なら、右辺 `e` の文脈は `T`。`n ?? 0` は、`n: usize | null` なら `0` が `usize` になる。式全体の型は `T`（右辺が `T` でなければ E2002）。`x?.f` は文脈を受け取らず、型は `F | null`。この式を比較のオペランドにすると、もう一方のリテラルは `F | null` の `F` を文脈にする（Q017 の `T | null` と `T` の比較）。

### Q015 リテラルの形と E2008
- 関連: §3.1
- 既定案:
  - 単項 `-` の直後が数値リテラルである式は、「負のリテラル」として 1 つのリテラルとみなす。`const m: i32 = -2147483648` は受理する。符号なしの文脈で負の値になるもの → E2008（`-0` は値が 0 なので受理する）。アンカーは `-` の位置。
  - 整数かどうかは値で判定する。`1.0`、`1e3`、`0x1F`、`0b1`、`0o7`、`1_000` は、範囲内なら整数型の文脈で受理する。`1.5` → E2008。
  - BigInt リテラル `1n` → E1000。旧式の 8 進数 `017` → E1000。
  - `f32` の文脈のリテラルは最も近い binary32 に丸める（JS への変換では `Math.fround` で包む）。有限のリテラルが丸めで ±Infinity になる場合は E2008。

### Q016 文字列リテラル型とその他のリテラル型
- 関連: §3.2
- 既定案:
  - 文字列リテラルの型は、文脈に文字列リテラル型（またはその union）があればそのリテラル型、なければ `string`。
  - `const k = "a"` は TS と同じくリテラル型 `"a"`、`let k = "a"` は `string`。
  - 数値リテラル型と `true` / `false` 型は書けない（E1000）。

### Q017 `===` / `!==` を使える型
- 関連: §3.1、§10.1
- 状況: §3.1 は「両辺は同じ型」とだけ言う。Struct は JS ではオブジェクトの同一性で比べ、C では値で比べることになり、両バックエンドで結果が食い違う。また `T | null` と `null` の比較は、字義どおりなら「同じ型」ではない。設計文書（非規範）は、値型には `===` を使わせない方針を書いている。
- 既定案: 使えるのは次の場合だけ。それ以外（レコード、`Array`、`Map`、`Set`、Struct、`Vec`、関数、`Result`、権限、`JsRef`）は E2002。アンカーは演算子。
  - 同じ数値型どうし、`boolean` どうし、`string` / 文字列リテラル型どうし（リテラルは文脈型付けされる）。
  - class のインスタンスどうし（JS の同一性）。
  - `T | null` と `null`（どちら側に書いてもよい）。
  - `T | null` の `T` が上の型なら、`T | null` と `T` の比較も許す。

### Q018 関係演算子 `<` `<=` `>` `>=` を使える型
- 関連: §3.1
- 既定案: 同じ数値型どうしだけ。`string` → E2002。

### Q019 文字列の `+` 連結（SPEC 修正候補）
- 関連: §3.1、§4
- 状況: §3.1 の `+` は数値型しか定めていない。許可リスト方式の原則に従うと、文字列の連結は拒否になる。
- 選択肢: (a) 拒否、(b) managed で `string + string` と `+=` を許す。
- 既定案: (a)。`string` に `+` / `+=` を使うと E2002。連結はテンプレートリテラルで書く。

### Q020 代入可能性（部分型関係）
- 関連: §3.2
- 状況: §3.2 の `Array<T>（不変）` の「不変」は、variance の invariant を指すと読める。`push` などの変更メソッドが許されているので、immutable の意味ではない。代入可能になる関係が列挙されていない。
- 既定案: `S` を `T` に代入できるのは、次のどれかに当てはまる場合だけ。
  1. 同一の型。レコードは構造的に同一性を判定する: フィールド名の集合、各フィールドの型、`readonly` の有無が完全に一致すること。別名の違いは問わない。class と interface は名前で判定する。
  2. `S` が `never`。
  3. `T` が `S | null`。`null` は `T | null` に代入できる。
  4. 文字列リテラル型 → `string`、およびそのリテラルを含む union。
  5. レコード → それをメンバに持つタグつき union。
  6. class → それが `implements` する interface。
  7. `Array<S>` → `ReadonlyArray<T>`、`ReadonlyArray<S>` → `ReadonlyArray<T>`（`S` を `T` に代入できること）。`Array` 自体は invariant。
  8. 関数型。引数は反変、戻り値は共変。
  9. `Vec<T>` / `Ref<Vec<T>>` / `Mut<Vec<T>>` → `Ref<Slice<T>>` / `Mut<Slice<T>>`、`Mut<X>` → `Ref<X>`（いずれも実引数の位置だけ。§3.3、§5.5）。
  10. 偽の権限 → 対応する権限型（Q038）。
- `readonly` の有無の違いも不一致として扱う。
- 追記（`Ref` / `Mut` の適用範囲。Q064 と合わせて読む）:
  - 型検査（P2）では、`Ref<X>` / `Mut<X>` の値を、読み書きの対象としては `X` として扱う。この読み替えは位置を問わない。実引数、`return`、フィールドへの格納、初期化のいずれでもよい。
  - 9 の変換（`Vec` → `Slice`、`Mut<X>` → `Ref<X>`）が「実引数の位置だけ」というのは、借用のまま渡せる場所が実引数だけ、という意味である。
  - 借用の値を実引数以外（`return`、フィールド、ローカル変数、値渡しの引数）に使ってよいかは、P3 で検査する。違反は E3004（Q064）で、P2 の E2002 にはしない。
  - 仮引数が `Ref<P>` / `Mut<P>` のとき、実引数の文脈型は `P` とする（Q014）。

### Q021 オブジェクトリテラルと配列リテラルの文脈型
- 関連: §3.2、§3.3
- 既定案:
  - オブジェクトリテラルには文脈型が必要。文脈がない `const p = { x: 1 }` は E2006（アンカーは変数名）。
  - タグつき union が文脈なら、`kind` の値でメンバを選ぶ。該当するメンバがない場合や、余剰・不足のフィールドがある場合は E2002（アンカーはリテラルの先頭）。
  - 短縮プロパティ `{ data, rate }` は許す。
  - 配列リテラルは、文脈があればその要素型を使う。文脈がない場合、空の `[]` は E2006、空でなければ要素の型をそろえる（数値リテラルだけなら `Array<f64>`）。

### Q022 アロー関数と関数式の注釈（SPEC 修正候補）
- 関連: §0.4、§9.2、付録 A-1
- 状況: §0.4 は「関数境界はすべて明示」と言うが、A-1 の `(t: Test) => { … }` には戻り値の注釈がない。
- 既定案:
  - `function` 宣言とメソッドは、全引数と戻り値の注釈が必須（E2006）。アンカーは、引数なら引数名、戻り値なら関数名（メソッド名、constructor は除く）。
  - アロー関数と関数式は、全引数の注釈が必須（E2006）。戻り値の注釈は省略でき、本体から推論する。
  - `ensures((r: R) => …)` の `r` にも注釈が必要。

### Q023 戻り値の全経路
- 関連: §3.2、付録 A-1
- 状況: 戻り値型が `void` でない関数が末尾まで到達した場合の規定がない。A-1 は、網羅的な `switch` の各 case で `return` し、その後に文がない。
- 既定案: 制御フロー上、末尾に到達しうる非 `void` 関数は E2002（アンカーは関数名、アロー関数なら `=>`）。次のものは「末尾に到達しない」とみなす。
  - `return`。
  - `never` 型の呼び出しを式文にしたもの（`panic(...)`）。
  - 両分岐が到達しない `if/else`。
  - 網羅的な `switch` で、全 case（または `default`）が到達しないもの。
  - 条件が字句上 `true` の `while (true)` / `for (;;)` で、`break` を含まないもの。

### Q024 `switch`
- 関連: §3.2、§4
- 既定案:
  - 判別式がタグつき union の `kind`、または文字列リテラル union の場合: 全メンバの `case` があるか、`default` があれば網羅的。足りなければ E2005。アンカーは `switch` キーワード。
  - それ以外の型（数値、`string`、`boolean`）: `default` が必須で、なければ E2005。
  - `case` のラベルは判別式の型のリテラルに限る。違反は E2002。重複したラベルは E2002。
  - フォールスルーは JS どおりに許す。
  - 追記: `string` 型の値（文字列リテラル union ではないもの）に対する `switch` も `default` が必須。全部の `case` を書いても網羅とはみなさない。

### Q025 絞り込みと `?.` / `??`
- 関連: §3.2
- 既定案:
  - 絞り込みが効く場所: `if` / `else` の分岐、`&&` / `||` の右辺、三項演算子の分岐、早期脱出（`if (x === null) return;` の後）、`switch` の各 case。
  - 対象: ローカル変数、引数、それらのフィールドパス。ただしパス上の全フィールドが `readonly` の場合だけ。間に再代入があれば絞り込みは解ける。
  - `?.` は、受け手が `T | null` の場合のプロパティアクセスとメソッド呼び出しだけ。`?.` の結果は `X | null`。非 null の受け手に `?.` を使うと E2002。`x?.[i]` と `f?.()` は E1000。
  - `??` は左辺が `T | null` の場合だけ。そうでなければ E2002。
  - 追記: `??` と `?.` の文脈型は Q014 の追記に従う。

### Q026 `as const`（SPEC 修正候補）
- 関連: §3.2
- 状況: `as const` は E1005 の例外とされている。しかし TS での効果（readonly タプル型、リテラル型）は STS の型の規則（タプル禁止）と合わない。
- 選択肢: (a) 型に影響しない no-op として受理、(b) 例外を取り消して E1005。
- 既定案: (a)。式の型は `as const` がない場合と同じにする（文脈型付けもそのまま）。`as const` 以外の `as` はすべて E1005。

### Q027 テンプレートリテラルの埋め込み式の型
- 関連: §4
- 既定案: `${}` に書けるのは、`string`、文字列リテラル型、数値型、`boolean` だけ。それ以外は E2002（アンカーは埋め込み式）。文字列化は JS のとおり（`f32` も JS の `String(x)` で書式化される）。strict / rt では、テンプレートリテラル自体が E4002 になる。
- 追記: `boolean` は `"true"` / `"false"` になる（JS の `String(x)`）。

### Q028 `void`、`never`、`null` の位置
- 関連: §3.1
- 既定案: `void` は戻り値型と関数型の戻り値にだけ書ける。それ以外の位置は E2002。`void` 関数の `return null;` も E2002。`never` と `null` はどこに書いてもよい。

### Q029 class、`new`、`Map` / `Set` の生成
- 関連: §3.2、§4、§12
- 状況: `new` 式も、`Map` と `Set` の作り方も、SPEC に書かれていない。
- 既定案:
  - `new C(args)` はユーザーの class に対して許す。
  - `new Map<K, V>()` と `new Set<T>()` は、引数なしの場合だけ許す（型引数は明示するか、注釈から推論する）。初期値の引数を渡すと E2001（アンカーは `Map` / `Set`）。
  - それ以外の組み込みの `new`（`new Array`、`new Promise`、`new Error` など）→ E2000（アンカーは名前）。`new Date` は Q006 で E5001。
  - `constructor` は 1 つまで書ける。フィールドは、宣言の初期化子か、constructor 本体の直下の文で `this.f = …` と無条件に代入して初期化する。初期化されないフィールドがあれば E2002（アンカーはフィールド名）。
  - `static` フィールドは Q054 に従う。

### Q030 型引数の推論
- 関連: §0.4
- 既定案: 推論は実引数から（リテラルを後回しにする。Q014）、次に文脈の型（注釈、仮引数、戻り値型）から行う。決まらなければ E2006（アンカーは呼び出し先の名前）。

## C. 組み込み

### Q031 `-1`、`NaN`、`undefined` を返す組み込み（SPEC 修正候補）
- 関連: §3.2、§10.7、§12
- 状況: `indexOf` と `findIndex` は見つからないと `-1` を返す。しかし添字型の `usize` では `-1` を表せない。`charCodeAt` は範囲外で `NaN` を返す。
- 選択肢: (a) 戻り値を `f64` にする、(b) §10.7 の正規化を広げて `usize | null` にする、(c) `i32` にする。
- 既定案: (b)。`Array.indexOf`、`Array.findIndex`、`string.indexOf` は `usize | null` を返し、`-1` を `null` に正規化する。`charCodeAt(i: usize): u16` は範囲外なら T002（トラップは §0.2 で許された差異）。`codePointAt(i: usize): u32 | null`。

### Q032 組み込みメンバのシグネチャ
- 関連: §12
- 状況: §12 には名前しかない。引数の数と型、コールバックの引数が決まっていない。
- 既定案: 組み込みも、ユーザー関数と同じく固定アリティとする。ただし次の表の `?` は、その位置の引数を省略できることを示す（組み込みの省略可能引数は、ユーザー側の E1008 とは別に扱う）。コールバックは、表の引数の先頭からの部分列だけを受け取れる。

  | 対象 | シグネチャ |
  | --- | --- |
  | `string` | `slice(start: usize, end?: usize)`、`indexOf(s: string): usize \| null`、`includes(s: string)`、`startsWith(s: string)`、`endsWith(s: string)`、`split(sep: string): Array<string>`、`trim()`、`toUpperCase()`、`toLowerCase()`、`padStart(n: usize, fill: string)`、`padEnd(n: usize, fill: string)`、`replaceAll(a: string, b: string)`、`charCodeAt(i: usize): u16`、`codePointAt(i: usize): u32 \| null` |
  | `String` | `fromCodePoint(c: u32): string`（引数は 1 つ） |
  | `Array<T>` | `push(x: T): usize`（1 引数）、`pop(): T \| null`、`slice(start?: usize, end?: usize)`、`map<U>(f: (x: T, i: usize) => U)`、`filter(f: (x: T, i: usize) => boolean)`、`reduce<A>(f: (acc: A, x: T, i: usize) => A, init: A)`、`forEach(f: (x: T, i: usize) => void)`、`find(f): T \| null`、`findIndex(f): usize \| null`、`some(f)`、`every(f)`、`includes(x: T)`、`indexOf(x: T): usize \| null`、`join(sep?: string)`、`concat(o: ReadonlyArray<T>)`（1 引数）、`reverse(): Array<T>`、`sort(cmp: (a: T, b: T) => f64): Array<T>`、`fill(x: T, start?: usize, end?: usize)` |
  | `ReadonlyArray<T>` | `Array<T>` のうち、`push`、`pop`、`reverse`、`sort`、`fill` を除いたもの |
  | `Map<K, V>` | `get(k): V \| null`、`set(k, v): Map<K, V>`、`has(k)`、`delete(k): boolean`、`size: usize`、`clear()`、`keys()`、`values()`、`forEach(f: (v: V, k: K) => void)` |
  | `Set<T>` | `add(x): Set<T>`、`has(x)`、`delete(x): boolean`、`size: usize`、`clear()`、`values()`、`forEach(f: (x: T) => void)` |
  | `Number` | `isFinite(x: f64)`、`isNaN(x: f64)`、`isInteger(x: f64)`、`parseFloat(s: string): f64`、`MAX_SAFE_INTEGER: f64`、`EPSILON: f64` |
  | `JSON` | `parse(s: string): unknown`、`stringify<T>(v: T): string`（1 引数。`T` は `cast` と同じ条件） |
  | `Promise` | `Promise.all<T>(ps: Array<Promise<T>>): Promise<Array<T>>` |

  - `includes` と `indexOf` の要素型は、`===` を使える型（Q017）に限る。それ以外は E2002。
  - `keys()` と `values()` の戻り値は `for...of` の対象にだけ書ける。変数に代入すると E2002。
  - `length` と `size` への代入は E2002。

### Q033 `Math` の引数型
- 関連: §3.1、§10.1、§12
- 既定案: `Math` の関数は `f64` を受け取って `f64` を返す。例外は `fround(x: f64): f32`。`min` と `max` は 1 個以上の `f64`。整数型と `f32` を渡すと E2002（明示的に変換する）。`PI` と `E` は `f64`。

### Q034 名前空間オブジェクトと変換関数
- 関連: §3.1、§12
- 既定案:
  - `Math`、`Number`、`JSON`、`String`、`Promise`、`Vec`、`OwnedCell`、`FakeClock`、`SeededRandom`、`MemoryLog`、`FakeFs`、`TestAlloc` は、メンバアクセスの受け手としてだけ書ける。裸の使用（`String(x)`、`const m = Math`）→ E2000。アンカーは名前。
  - 変換関数は `f64`、`f32`、`i8`、`i16`、`i32`、`u8`、`u16`、`u32`、`usize` の 9 つで、引数は任意の数値型 1 つ。`number(x)` は存在しない（E2000）。

### Q035 JS の例外を投げる組み込みと、スタックの枯渇
- 関連: §0.2、§8、§12
- 状況: `JSON.parse`（構文エラー）、`String.fromCodePoint`（範囲外で RangeError）、`padStart` / `padEnd`（長すぎる長さ）、`Array.push`（長さが 2^32−1 を超える）は JS の例外を投げる。深い再帰でもスタックが枯渇する。STS には例外がなく、対応するトラップコードもない。
- 選択肢: (a) 専用の T コードを新設、(b) 組み込みの定義として `panic` を呼ぶものとみなす（T006）、(c) `JSON.parse` を `Result` を返す形に変える。
- 既定案: (b)。これらは「組み込みが内部で `panic` を呼ぶ」と定義する（T006 の意味は変えない）。アンカーは呼び出し先の名前。スタックの枯渇もいまは T006 とし、アンカーは枯渇が起きた呼び出し。適合テストでは、この挙動に依存する実行例を書かない。

### Q036 `CastError` と `JsError` の形
- 関連: §3.2、§7.4
- 既定案: どちらも `{ readonly code: string; readonly message: string }`（`IoError` と同じ形）。`CastError.code` は `"cast"`、`JsError.code` は JS の例外の `name`。`message` の文面はテストで固定しない。

### Q037 `ok` / `err` の型
- 関連: §8
- 既定案: `ok(v)` と `err(e)` の `Result<T, E>` は文脈型から決める。文脈がなければ E2006（アンカーは `ok` / `err`）。

### Q038 `System` のメンバと偽の権限の API
- 関連: §7.1、§9.2
- 既定案:
  - `System` のメンバは `alloc: Alloc`、`fs: Fs`、`clock: Clock`、`random: Random`、`log: Log`、`js: Js` の 6 つだけ。
  - 偽の権限は、対応する権限型に代入できる（Q020 の 10）。
    - `FakeClock.create(startMs: f64): FakeClock`。`nowMs()` と `advance(ms: f64): void` を持つ。
    - `SeededRandom.create(seed: u32): SeededRandom`。`Random` と同じメソッドを持つ。乱数の算法は未定なので、テストは具体的な値に依存しない。
    - `MemoryLog.create(): MemoryLog`。`Log` のメソッドと、`entries(): Array<{ readonly level: "info" | "warn" | "error"; readonly message: string }>` を持つ。
    - `FakeFs.create(): FakeFs`。`Fs` と同じメソッドを持ち、最初は空。存在しないパスの `readText` は `err({ code: "ENOENT", … })` を返す。
    - `TestAlloc.create(): Alloc`。
  - テストの外でも使える（§12 の大域名なので）。

## D. 層

### Q039 指示子
- 関連: §2
- 既定案:
  - ファイルの指示子は、ファイルの最初の文（コメントは除く）に書く。import より前に置く。
  - 関数の指示子は、本体の最初の文に書く。
  - 関数の指示子は、ファイルの指示子より優先する。
  - ファイルの指示子が適用されるのはモジュール直下の `function` 宣言だけ。class のメソッドと `test` の本体は常に managed。
  - メソッド本体、アロー関数、関数式の中の指示子 → E1000。
  - 指示子を 2 つ書くと E1000。未知の指示子と `"use unsafe"` も E1000。アンカーは指示子の文字列リテラル。

### Q040 strict の権限型（SPEC 修正候補）
- 関連: §3.3、§6、付録 A-3
- 状況: §3.3 は strict で使える型に権限型を挙げていない。しかし A-3（strict）は `alloc: Alloc` を受け取り、§6 は「rt では権限型のパラメータを禁止」と言うので、strict では許すと読める。
- 既定案: strict は、すべての権限型を引数と値として許す。ただし `string` は strict に存在しないので、`Log` や `Fs` のメソッドは文字列を渡す時点で E4002 になる。rt の権限型の引数は E4006（アンカーは引数の型注釈）。

### Q041 strict の `OwnedCell`（SPEC 修正候補）
- 関連: §3.3、§5.6、§6
- 状況: §6 は rt で `OwnedCell` を禁止しているので、strict では使えるとも読める。しかし `OwnedCell` は managed の値（§5.6）で、§3.3 の型一覧にない。
- 既定案: strict でも rt でも E4002（アンカーは型注釈か、`OwnedCell` の名前）。

### Q042 strict / rt の `panic` と文字列（SPEC 修正候補）
- 関連: §3.3、§8
- 状況: `panic(msg: string)` を使うには文字列が要るが、strict / rt に文字列型はない。
- 既定案: `panic` の実引数が文字列リテラルの場合に限り、strict / rt でも受理する。それ以外の文字列の式は E4002。

### Q043 strict / rt のタグつき union と `Result`（SPEC 修正候補）
- 関連: §3.3、§8
- 状況: タグつき union は、`kind` に文字列リテラル型を持つレコードで定義される。しかし strict には文字列型もレコード型もない。`Result` もレコードの union である。
- 既定案: strict / rt では、全フィールドが `readonly` で、各フィールドの型が Copy 型か文字列リテラル型であるレコード型を、Copy の Struct とみなして受理する。文字列リテラル型は、その `kind` フィールドと、`===` / `switch` の比較にだけ使える。`IoError` などを含む `Result` は Copy でないので E4002。

### Q044 managed 専用の組み込みを strict / rt から呼ぶ
- 関連: §10.1、§12
- 既定案: E4001（アンカーはメンバ名、例 `sin`）。対象は `Math` の managed 専用関数、`Number`、`JSON`、`String`、`Promise`、`cast`、`test` と `Test` のメソッド、偽の権限の生成。

### Q045 関数を値として使う
- 関連: §2、§3.2
- 既定案: managed では、managed の `function` 宣言を値として使える（`xs.map(double)`）。strict / rt の関数を値として使うと、どの層でも E4003（アンカーは識別子）。メソッドの参照は §3.2 により E2002。

### Q046 rt の再帰の検出
- 関連: §6、§10
- 既定案: import を通じて、プログラムの全モジュールの rt 関数の呼び出しグラフを作る。強連結成分（自己ループを含む）に入る呼び出しごとに E4005 を出す。アンカーは呼び出し先の名前。1 ファイルだけの検査では、そのファイル内の辺だけで判定する。

## E. 所有権

### Q047 managed での `Vec`、`Struct`、`Alloc`
- 関連: §5.6、§9.2、付録 A-2
- 既定案:
  - managed のコード（テスト本体を含む）でも、`Vec` と所有型の Struct をローカル変数・引数・戻り値に置ける。§5.2 〜 §5.5 の規則が適用される。
  - `v[i]`、`v[i] = x`、`v.length`、`v.push(x)` も使える。A-2 の `t.eq(a[0], 6)` は受理する。
  - Copy の Struct は、所有型ではないので managed のどこに置いてもよい（レコード、`Array`、`Map` の値など）。
  - `Alloc` は `sys.alloc` か `TestAlloc.create()` から得る。

### Q048 E3007 の対象と B-8 の位置
- 関連: §5.6、付録 B-8
- 状況: B-8 には違反の候補が 3 か所ある。戻り値の注釈 `Array<Vec<f32>>`、ローカル変数の注釈、`push` の実引数の 3 つ。§11 の E3007 は「値を入れた」と書いている。
- 選択肢: (a) 値を格納する式で報告する、(b) 所有型を含む型そのものを拒否する（位置は最初の型注釈になる）。
- 既定案: (a)。型 `Array<Vec<f32>>` 自体は受理し、所有型の値を managed のコンテナ（レコード、class のフィールド、`Array`、`Map`、`Set`）に格納する式で E3007 を出す。アンカーは格納される値の式。B-8 は 3:11（`Vec.create` の `Vec`）になる。

### Q049 ジェネリクスの本体での型パラメータ
- 関連: §3.2、§3.3、§5
- 既定案: 関数本体の中では、型パラメータを所有型（移動のみ）として検査する。managed のユーザー定義ジェネリクスを所有型で具体化した場合でも、格納の違反は Q048 のとおり本体の中で E3007 になる。

### Q050 `Ref` を通した書き込み
- 関連: §5.5
- 既定案: 次はすべて E3006。アンカーは、代入なら代入先の式の先頭、呼び出しならメンバ名。
  - `Ref` で受け取った値への書き込み（`s.x = 1`、`s[i] = x`）。
  - `Mut` を要するメソッド（`push`、`fill` など）の受け手に `Ref` を使うこと。
  - `Ref` を `Mut` パラメータに渡すこと（§5.5 の本来の場合）。

### Q051 `Ref<T>` / `Mut<T>` の `T` の条件違反
- 関連: §5.5
- 既定案: `T` が所有型でも `Slice<U>` でもない場合（`Ref<f32>`、Copy の Struct など）→ E2002。アンカーは型引数。

### Q052 分割代入
- 関連: §4、§5.3
- 既定案: `const { a, b: c } = p` の形だけを許す。フィールドの部分集合でよく、別名も許す。`let` の分割代入、既定値、残余、入れ子、引数での分割代入、`for…of` での分割代入は E1000（既定値は E1008）。所有型の Struct を分割すると全体が移動する。取り出さなかった所有型フィールドは破棄される。

### Q053 オブジェクトスプレッド
- 関連: §4
- 既定案: すべての層で許す（strict / rt では Struct に対して）。スプレッド元が所有型なら、元の値は移動する。結果の型は、注釈の型と構造的に一致すること（Q020 の 1）。一致しなければ E2002。配列のスプレッドは managed のみで、strict / rt では E4002。呼び出しの実引数でのスプレッドは E1000。

## F. モジュール

### Q054 モジュール直下の `const`
- 関連: §1
- 状況: 「不変なレコード・配列のリテラル」の基準が決まっていない（`Array` は変更できる）。また、リテラル以外の初期化式のコードもない。
- 既定案:
  - 許す初期化式: 数値リテラル（負のものを含む）、文字列リテラル、置換のないテンプレート、`true`、`false`、`null`、および、それらだけからなる、全フィールドが `readonly` のレコードリテラルと、型が `ReadonlyArray<T>` の配列リテラル（入れ子も可）。
  - 型が `Array`、`Map`、`Set`、class、`Vec` の場合、または上記以外の初期化式（関数呼び出し、`new`、他の定数の参照、演算）は E5002。アンカーは初期化式。
  - 型注釈がなければ E2006（アンカーは変数名）。
  - class の `static` フィールドは `readonly` 必須で、初期化式は上と同じ条件。違反は E5002。
  - モジュール直下の、§1 にない文（式文、`if` など）→ E1000。

### Q055 関数内の宣言と `let` の初期化
- 関連: §1、§4
- 既定案: 関数本体の中の `function` 宣言、`type`、`interface`、`class` は E1000。初期化子のない `let` も E1000（アンカーは変数名）。

## G. 契約とテスト

### Q056 契約が参照できるもの
- 関連: §9.1
- 既定案:
  - `requires` が参照できるのは、引数、モジュール直下の `const`、§12 の組み込み関数、決定的な関数（§7.3）の呼び出し。それ以外の名前は E6002（アンカーはその識別子）。
  - `ensures` は、`r`、Copy 型の引数、モジュール直下の `const`、上と同じ関数。
  - `ensures` は各 `return` の時点で評価し、引数はその時点の値を見る（JS のクロージャと同じ）。
  - `async` 関数の `ensures` は E6001。
  - 追記: `ensures` から `Ref` / `Mut` の引数（`Ref<Vec<T>>`、`Mut<Slice<T>>` など）と、所有型の値渡しの引数を参照すると E6002。「Copy 型の引数」に当たらないため。`out.length` のようにフィールドを読むだけでも同じ。アンカーはその引数の識別子。`requires` は §9.1 で引数全般を参照できるので、借用引数も参照できる（付録 A-2）。

### Q057 契約の位置
- 関連: §9.1
- 既定案:
  - `requires` / `ensures` は、`function` 宣言とメソッドの本体の先頭にだけ書ける。アロー関数（テスト本体を含む）に書くと E6001。
  - 順序は「指示子 → `requires`* → `ensures`*」。順序違反は E6001（アンカーは後ろに来た誤りの呼び出しの名前）。
  - `invariant` は、`while`、`do`、`for`、`for…of` の本体（ブロック）の先頭に 0 個以上書ける。毎反復の最初に評価する。
  - 契約の呼び出しを式の一部にすると E6001。

### Q058 `Test` API の細部
- 関連: §9.2
- 既定案:
  - `test` の第 1 引数は文字列リテラル、第 2 引数は `(t: Test) => …` のアロー関数。違反は E2002。名前の重複は許し、宣言の順に実行する。
  - `t.ok` / `t.eq` が失敗すると、そのテストはその場で終わる。ほかのテストは続ける。
  - テストの中のトラップ（`t.traps` の外）は、そのテストの失敗になる。
  - `t.eq` の数値比較は SameValueZero（NaN は NaN と等しく、+0 は −0 と等しい）。レコードと `Array` は構造的に比べる。
  - `t.traps` の第 1 引数は `"T001"` 〜 `"T010"` の文字列リテラル。違反は E2002。
  - テスト本体は `sts check` でも検査する。

## H. 実行

### Q059 `expect-output` の定義
- 関連: §7.1、ROADMAP 段階 0
- 状況: 何が出力として比べられるのか、`Log` の書式が決まっていない。
- 既定案:
  - `sts run` は、本物の `System` で `main` を実行する。
  - `log.info(msg)` は `msg + "\n"` を stdout に書く（接頭辞なし）。`warn` と `error` は同じ書式で stderr に書く。
  - 比べるのは stdout だけ。`// expect-output: <text>` の 1 行が stdout の 1 行に対応する（`: ` の直後から行末まで。末尾の空白は保持する）。stdout は、それらを `"\n"` でつなぎ、末尾に `"\n"` を付けたものと完全に一致すること。
  - 出力が空であることを期待するときは、`// expect-no-output` と明示する（`expect-output` を 0 行にはできない）。`expect-trap` だけを書いたときは、stdout を比べない。
  - `expect-trap` と併記すると、トラップより前の stdout も比べる。

### Q060 トラップの報告形式と位置
- 関連: §8、§10、§10.1
- 既定案:
  - 位置は `docs/DIAGNOSTICS.md` のトラップ表のアンカーに従う（Q002 の一般則）。
  - `sts run` がトラップで終わると、終了コードは 3。`--json` のときは、stderr に 1 行の `{"kind":"trap","code":"T001","file":"…","range":{"start":{"line":8,"col":14},"end":{…}}}` を出す。
  - コンパイルエラーの終了コードは 1、正常終了は 0。

### Q061 `sts run` の入口
- 関連: §7.1
- 既定案: 対象のファイルが `export function main(sys: System): void` か `Promise<void>` を持つこと。`main` は managed でなければならない。満たさない場合は診断ではなく CLI のエラー（終了コード 2）。実行ファイル中の `test(...)` は無視する。

### Q062 決定的な関数の判定
- 関連: §7.3
- 既定案: パラメータの型を推移的に調べる。レコードのフィールド、class のフィールド、union のメンバ、`Array` / `Map` / `Set` / `Promise` / `Result` の型引数、Struct のフィールドを含めて、権限型、関数型、interface、`unknown`、`JsRef` が現れなければ決定的とする。問い合わせの手段（CLI や API）は段階 1 で `docs/DECISIONS.md` に決める。

## J. 適合テスト作成で見つかった穴（追加）

### Q064 所有型が要る場所で `Ref` / `Mut` の値を使う
- 関連: §5.5、§11
- 状況: `Mut<Vec<f32>>` の引数 `v` を、`{ data: v }`（フィールド型が `Vec<f32>`）に入れたり、戻り値型が `Vec<f32>` の関数で `return v` としたりする場合。型の不一致（E2002、P2）とも、二級性の違反（E3004、P3）とも読める。Q003 のフェーズ順では E2002 と読むと先に出てしまう。
- 選択肢: (a) E3004、(b) E2002。
- 既定案: (a)。型検査（P2）では、`Ref<T>` / `Mut<T>` の値を、読み書きの対象としては `T` として扱う。借用かどうかは P3 で検査し、格納は E3004（§5.5 二級性の 2）、`return` は E3004（同 3）にする。アンカーは格納される値の式と `return` の式（`docs/DIAGNOSTICS.md` の E3004 の形ごとの行）。値渡しのパラメータに借用を渡す場合も同じく E3004 とする（移動できないため）。P2 での読み替えの範囲は Q020 の追記に書いた。

### Q065 受け手と実引数が重なる E3005 は、v0 ではテストを書けない
- 関連: §3.3、§5.5
- 状況: §5.5 は「メソッド呼び出しの受け手も実引数の 1 つとして数える」と言う。しかしメソッドを持つ所有型は `Vec` / `Slice` だけで、そのメソッドの実引数は Copy 型（`push(x: T)`、`fill(x: T)`、`slice(a: usize, b: usize)`）に限られる。Copy の評価結果を持つ式の借用はその時点で終わる（§5.5）ので、受け手と実引数の衝突は起きない。
- 選択肢: (a) 規則は実装するが、適合テストは求めない、(b) SPEC から当該の文を外す。
- 既定案: (a)。E3005 の適合テストは実引数どうしの衝突（付録 B-2 の形）で書く。所有型を取るメソッドが入る段階（非 Copy 要素の `Vec` など、§13）で受け手のケースを足す。

### Q066 rt での `Vec.create` は必ず E4006 を伴う
- 関連: §6、§11
- 状況: rt 関数は `Alloc` を受け取れない（E4006）。大域の `Alloc` もないので、rt の `Vec.create(alloc, n)` は常に、引数の型注釈の E4006 と組みになる。引数の注釈は本体より前にあるので、最初の診断は E4006 になる。
- 既定案: これは仕様どおりで、変更しない。E4004 の適合テストは借用した `Vec` への `push`（付録 B-4 の形）で書く。rt の `Vec.create` を含むファイルの期待は、最初の診断の E4006 にする。

### Q067 1 つの呼び出しで、別々の実引数に同じ変数の一時的な借用がある場合
- 関連: §5.5
- 状況: `g(v.push(x), v.length)` のように、ある実引数の中で `v` を `Mut` で使い、別の実引数で `v` を `Ref` で使う場合の排他性が決まっていない。
- 既定案: 受理する。E3005 の対象は、呼び出し先の `Ref` / `Mut` パラメータへの借用（場所式そのものを渡すもの）と値渡しの移動、および受け手だけとする。実引数の式の中の借用は、§5.5 の「評価結果が Copy 値なら、その式の中の借用は評価が終わった時点で終了する」により、その実引数の評価で終わる。評価は左から右（§10.1）なので、上の例は `push` の後の長さを渡す。

### Q068 汎用コンテナでの型パラメータ（Q049 の補足と見直し候補）
- 関連: §3.2、§5.6、Q049
- 状況: Q049 は型パラメータを本体の中で所有型として検査すると定めている。字義どおりに当てると、managed のジェネリック関数で `T` の値を `Array<T>` に入れることや、`Box<T>`（`{ readonly value: T }`）を作ることが、常に E3007 になる。`b.value` で取り出すことも E3003（部分移動）か移動になり、managed の汎用コードがほぼ書けなくなる。
- 選択肢: (a) Q049 のまま、(b) managed では、所有型による具体化を呼び出し側で禁止し、本体では `T` を所有型として扱わない、(c) 制約の構文を足す（構文を増やさない方針に反する）。
- 既定案: Q049 の趣旨を変える提案なので、承認されるまで Q049 のまま（a）とする。(b) は見直し候補として次のとおり記録する。
  - managed のジェネリック関数・型を、所有型の型引数で具体化すると E3007。アンカーは明示された型引数か、推論なら呼び出し先の名前。
  - そのかわり managed の本体では、`T` の値をコンテナに格納でき、フィールドから取り出せる（移動とはみなさない）。
  - strict / rt の本体は Q049 のまま（`T` は移動のみ）。
  - 適合テストは決着するまで managed の汎用コンテナで `T` を格納・取り出すケースを書かない。

### Q069 strict / rt での `async` / `await`
- 関連: §3.3、§4
- 状況: `async` / `await` は managed のみ（§4）だが、違反のコードがない。
- 既定案: E4002（`Promise` は §3.3 の型ではない）。アンカーは `async` キーワード。strict / rt の本体の `await` は、関数自体が `async` でなければ TS の構文上ありえないので、`async` の E4002 だけを出す。戻り値の注釈 `Promise<T>` もあるが、`async` キーワードのほうが前にあるので、最初の診断は `async` になる。

## K. 段階 1 の実装で見つかった穴

### Q070 パーサ自体の構文エラー
- 関連: §0.1、§11、Q003
- 状況: TS のパーサが構文エラーを出すソース（`function f(: void {}` など）のコードが決まっていない。§11 に該当するコードはない。
- 選択肢: (a) E1000（仕様にない構文）とする、(b) 専用コードを新設する（SPEC §11 の改訂が要る）。
- 既定案: (a)。P1 の診断とし、アンカーはパーサが報告した位置（`range` はパーサの範囲）。構文エラーのあるファイルは、許可リストの検査をしない（壊れた AST からの二次エラーを避ける。Q003 のカスケード抑止）。パーサが複数のエラーを出したら全部出す。

### Q071 SPEC にない複合代入演算子
- 関連: §3.1、Q008
- 状況: §3.1 が挙げる複合代入は `+=`、`-=`、`*=` だけで、`/=`（DIAGNOSTICS の E2007）と `%=`、`**=`（Q008）は別の文書に出てくる。ビット演算の複合代入（`&=`、`|=`、`^=`、`<<=`、`>>=`、`>>>=`）と論理代入（`&&=`、`||=`、`??=`）はどこにも書かれていない。
- 選択肢: (a) 許可リストどおり E1000、(b) 対応する二項演算と同じ規則で受理する。
- 既定案: (a)。アンカーは演算子トークン。`+=`、`-=`、`*=`、`/=`、`%=`、`**=` は受理し、型の規則は P2 に任せる。

### Q072 モジュール直下の `const` の不変性を P1 で決めきれない
- 関連: §1、Q003、Q054
- 状況: E5002 は P1 だが、「全フィールドが `readonly` のレコード」「型が `ReadonlyArray<T>`」の判定には、注釈の型の別名を解決する必要がある（`const ORIGIN: Point = { … }`）。P1 は構文だけを見る。
- 選択肢: (a) P1 は構文で判定できる部分だけを見て、残りを P2 で E5002 として出す、(b) P1 で同じファイルと import 先の別名をたどる。
- 既定案: (a)。P1 は初期化式の形（Q054 のリテラルだけからなるか）と、注釈に直接見える可変性（先頭が `Array`、`Map`、`Set`、`Vec` の型参照、`readonly` のないプロパティを持つ型リテラル）を検査する。別名の先の `readonly` と `ReadonlyArray` は P2 で検査し、違反は同じ E5002（アンカーも同じ初期化式）で出す。このため E5002 だけは P2 にも現れうる。

### Q090 整数演算の -0 と `rem` の範囲
- 関連: §3.1、§10、§10.1
- 状況: JS では `-3 * 0`、`Math.trunc(-1 / 2)`、`-4 % 2`、単項 `-0` が -0 になる。整数型に -0 は存在しない。また §3.1 は `divTrunc` と `rem` の両方に「結果が範囲外なら T001」と書くが、`rem` の結果は常に範囲内（i8 の `rem(-128, -1)` は数学的に 0）。C の `INT_MIN % -1` は未定義動作。
- 選択肢: (a) 整数演算の結果の -0 は +0 に正規化し、`rem` は T001 を起こさず 0 を返す、(b) `rem(MIN, -1)` も T001 にする。
- 既定案: (a)。ランタイムは整数の `+ - * neg divTrunc rem` と変換の結果に `+ 0` を足して -0 を消す。f64 / f32 の -0 は保つ。C バックエンドは `MIN % -1` を 0 として実装する（段階 2）。

### Q091 ランタイムの呼び出し形（型引数と位置）
- 関連: §10、Q002、Q060
- 状況: 型引数は実行時に消える。`Vec.create<T>`、`cast<T>`、`js.decode<T>` は T の情報が要る。トラップの位置の渡し方も決まっていない。
- 選択肢: (a) 各関数の末尾の引数で渡す、(b) 呼び出しごとに別の関数を生成する。
- 既定案: (a)。`Vec.create(alloc, capacity, elem)` の `elem` は数値型名（`"i32"` など）か `"other"`（配列）。`cast(x, desc)` と `js.decode(v, desc)` の `desc` は `TypeDesc`（`@sts/runtime-js` の `result.ts`）。トラップしうる関数と `Test` のメソッドは、最後の引数に省略可能な `Pos`（`{ file, line, col }`）を取る。`ensures(pred, r, pos)` は述語と戻り値を受け取り、変換部がすべての `return` で呼ぶ。

### Q092 `cast` と `f32`、レコードの厳密さ
- 関連: §3.2、§7.4
- 状況: `cast<f32>(x)` が、丸めると変わる f64 を受理するかが決まっていない。レコードの余剰プロパティの扱いも同様。
- 既定案: `f32` は、NaN か `Math.fround(x) === x` のときだけ受理する（暗黙に丸めない）。レコードは閉じた正確な型なので、余剰プロパティも不足も `err`。`Array` は要素を全部検査し、成功時は同じ参照を返す（コピーしない）。タグつき union は、どれかのメンバに合えば受理する。

## L. 段階 1 の型検査（P2）で見つかった穴

### Q073 E5001 の修正候補の形
- 関連: §7.2、§11、Q006
- 状況: §7.2 は E5001 に「対応する権限を受け取る修正候補を付ける」と言うが、どの大域名がどの権限に対応するか、修正の編集が何かを決めていない。
- 選択肢: (a) 対応のある名前だけ、囲む関数に権限の引数を足す編集を付ける、(b) 呼び出しの書き換えまで含める（`console.log(x)` → `log.info(x)`）、(c) 修正候補を付けない。
- 既定案: (a)。対応は `console` → `Log`、`Date` と `performance` → `Clock`、`Math.random` → `Random` の閉じたリスト。`data` は `{ name, authority }`。囲む名前つき関数（`function`、メソッド、constructor）があれば、その引数リストの末尾に `log: Log` の形（名前は権限型の小文字）を挿入する編集を 1 つ付ける。呼び出し自体は書き換えない（API の形が違うので機械的に直せない）。対応のない名前（`fetch`、`process` など）と、囲む関数のない位置（`test` の本体の直下など）には修正候補を付けない。

### Q074 戻り値が `void` のコールバック
- 関連: §3.2、Q020 の 8、Q022、Q032
- 状況: `xs.forEach((x: i32) => out.push(x))` の本体は `usize` を返す。Q020 の 8（戻り値は共変）を字義どおりに当てると、`(x: i32) => usize` を `(x: T, i: usize) => void` に渡せない。`t.traps("T003", () => u8(300))` も同じ。
- 選択肢: (a) 拒否する（ブロック本体で書かせる）、(b) 戻り値が `void` の文脈では、式本体を「値を捨てる文」として扱う。
- 既定案: (b)。文脈の戻り値型が `void` のとき（ユーザーの関数型を含む）、アロー関数の式本体は型を検査するだけで、`void` との一致は求めない。その関数式の型は `=> void` になる。式でない関数値（`xs.forEach(log)` の `log` など）については、組み込みのコールバック（Q032 の `prefix`）の戻り値が `void` のときだけ、どの戻り値の関数も渡せる。

### Q075 表にない E2002 の形のアンカー
- 関連: §11、Q002、`docs/DIAGNOSTICS.md`
- 状況: 次の E2002 の形のアンカーが決まっていない。
- 既定案（`docs/DIAGNOSTICS.md` の形ごとの表に追記した）:
  - 実引数の個数の誤り: 呼び出し先の名前（Q002 の 2）。型引数の個数の誤りも同じ。
  - `implements` した interface のメソッドがない、またはシグネチャが一致しない: `implements` 句のその型参照の先頭。
  - `readonly` のフィールド、`length` / `size`、`const` への代入: フィールドならメンバ名、変数なら識別子。
  - `T | null` の受け手へのメンバアクセス、非 null の受け手への `?.`: メンバ名。
  - 型引数の個数の誤り（`Array<i32, i32>`）: 型参照の先頭。
  - 型引数が制約 `T extends I` を満たさない: 明示した型引数ならその型引数の先頭、推論したなら呼び出し先の名前。

### Q076 タグつき union の共通フィールドの読み取り
- 関連: §3.2、Q007、Q025
- 状況: `switch (s.kind)` を書くには、絞り込む前の union から `kind` を読める必要があるが、union のメンバアクセスの規則がない。
- 既定案: タグつき union では、全メンバが持つフィールドを読める。型は各メンバのフィールド型の union。`readonly` は全メンバで `readonly` のときだけ。タグつきでない union（`T | null`、文字列リテラル union）のメンバアクセスは E2002（`T | null` は絞り込んでから読む）。

### Q077 引数への再代入
- 関連: §4、§5.5
- 状況: §5.5 は「`const` と `let` の違いは再代入の可否だけ」と言うが、引数に再代入できるかは書いていない。
- 選択肢: (a) JS どおり許す、(b) 禁止する。
- 既定案: (a)。値渡しの引数は `let` と同じく再代入できる（絞り込みは解ける）。`Ref` / `Mut` の引数への再代入の可否は段階 2（P3）で決める。

### Q078 `ensures` が参照できる「Copy 型の引数」の範囲
- 関連: §5.1、§9.1、Q056
- 状況: §5.1 の Copy 型は数値型、`boolean`、Copy の Struct、Copy 型の union だけで、`string`、managed のレコード、`Array` などはどちらでもない。字義どおりなら、`ensures` から `string` の引数を参照すると E6002 になる。Q056 の追記が問題にしているのは借用引数と所有型の値渡し引数だけである。
- 選択肢: (a) §5.1 の Copy 型に限る、(b) 借用（`Ref` / `Mut`）でも所有型でもない引数を許す。
- 既定案: (b)。E6002 にするのは、`Ref` / `Mut` の引数と、所有型（非 Copy の Struct、`Vec`）の値渡しの引数だけ。

### Q079 閉じたリストの外で、実装が受理または拒否しているもの
- 関連: Q009、Q017、Q020
- 状況: 次の 3 点は Q009、Q017、Q020 の列挙に入っていない。
  - 制約 `T extends I` を持つ型パラメータの値を、`I` 型の場所に渡す（Q020 の列挙にない）。制約のメソッドを呼べることは §3.2 から読めるが、代入は書かれていない。
  - 両辺が `T | null` の `===`（Q017 は「`T | null` と `null`」「`T | null` と `T`」だけを挙げる）。
  - `export { x }` の `x` がそのモジュールで宣言も import もされていない（Q009 は import 側だけを挙げる）。
- 既定案:
  - 型パラメータはその制約の interface に代入できる。
  - 両辺が `T | null` で、`T` が Q017 の型どうしなら `===` を許す。
  - 存在しない名前の `export { … }` は E7001。アンカーはその名前（`a as b` なら `a`）。P1 で出す。

## M. 型の位置と呼び出しの条件（段階 1 の穴埋め）

### Q080 union の合法性のコード
- 関連: §3.2、Q004、Q003、Q072
- 状況: §3.2 は「許されない union」を禁止するだけで、コードがない。Q004 の字義どおりなら E1000 だが、判定にはメンバの型（別名の先のレコードと `kind`）が要り、P1 では決められない。E1000 は P1 のコードとして扱われ、ハーネスも P1 の出力と突き合わせる。
- 選択肢: (a) E1000 を P2 から出す、(b) P1 が別名をたどる（Q072 の (b)）、(c) P2 の E2002 にする。
- 既定案: (c)。アンカーは union の型ノードの先頭。許すのは、`null` を除いたあとの形が次のどれかのとき: 1 つの型（`T | null`）、すべて文字列リテラル、各メンバがレコードで `kind` が互いに異なる文字列リテラル型。`Shape | null`（`Shape` がタグつき union）は許す。intersection は P1 の E1000 のまま。型パラメータを含む union（`T | string`）は、タグつきでも `T | null` でもないので拒否する。

### Q081 `Map` の `K` と `Set` の `T`
- 関連: §3.2、Q051
- 既定案: `string`、数値型、`boolean` のみ。文字列リテラル型や union、型パラメータの具体化後の型は検査しない（型パラメータそのものは通す）。違反は E2002。アンカーは型引数の先頭（`new Map<K, V>()` の明示した型引数も同じ）。

### Q082 `void` を書ける位置の追記（Q028）
- 関連: §3.1、§7.1、Q028
- 状況: Q028 は「戻り値型と関数型の戻り値」だけとするが、`Promise<void>`（§7.1 の `main`、非同期のテスト）が書けなくなる。
- 既定案: Q028 の位置に加えて、`Promise` の型引数だけに書ける。それ以外（引数、レコードのフィールド、ローカルの注釈、union のメンバ、他の型引数）は E2002。アンカーは `void` の型ノード。型の別名の本体に書いた `void` も E2002。

### Q083 `includes` / `indexOf` の要素型の違反のアンカー
- 関連: Q002、Q017、Q032
- 状況: 違反は実引数ではなく受け手の要素型にあるので、Q002 のどの項にも当たらない。
- 既定案: E2002。アンカーはメンバ名（`xs.includes(y)` の `includes`）。要素型が `===` を使える型（Q017）かどうかは、`T | null` なら `T` で判定する。型パラメータは使えない（`===` も使えないため）。

### Q084 `cast`、`js.decode`、`JSON.stringify` の `T`
- 関連: §3.2、§7.4、Q032、Q092
- 状況: §3.2 は `T` を「プリミティブ、レコード、タグつき union、`Array`、`T | null` の組み合わせ」に限る。検査の対象が細かく決まっていない。
- 既定案: 次だけを許す（実行時の `TypeDesc` と同じ）。数値型、`boolean`、`string`、`null`、文字列リテラル型、`Struct` でないレコード（全フィールドが再帰的に許される型）、それらの union（合法なもの）、`Array<許される型>`。`unknown`、`ReadonlyArray`、`Map`、`Set`、class、interface、関数型、権限型、`Struct`、型パラメータは E2002。アンカーは明示した型引数の先頭、推論なら呼び出し先の名前（`cast` / `stringify` / `decode`）。`JSON.stringify` は引数の型から推論した `T` に同じ条件を課す。

### Q085 再帰する型の別名
- 関連: §3.2、D009
- 状況: 別名が自分自身（相互も含む）を参照する形を、実装は診断を出さずにエラー型にして受理していた。レコードの同一性が構造で決まるため、再帰を許すと `same` と `assignable` に不動点が要る。
- 選択肢: (a) 拒否する、(b) 遅延する別名の型を導入して受理する。
- 既定案: (a)。E2002、アンカーは循環を閉じる型参照の先頭。再帰するデータは class（名前で同一性を判定する）で書く。(b) は段階 1 の範囲を超えるので、必要になったら提案する。

### Q086 型引数・Struct のフィールド・`Test.eq` の条件
- 関連: §3.3、§9.2
- 既定案（いずれも E2002）:
  - `Struct<{…}>` のフィールドの型は、数値型、`boolean`、`Struct`、`Vec<T>` のみ（型パラメータは通す）。アンカーはフィールドの型注釈の先頭。
  - `Vec<T>` と `Slice<T>` の `T` は Copy 型のみ（§3.3「v0」）。アンカーは型引数の先頭。`Vec.create<T>` の `T` も同じ（明示した型引数の先頭、推論なら `create`）。
  - `t.eq<T>(a, b)` の `T` は、所有型（`Vec`、非 Copy の `Struct`）、関数型、権限型、`OwnedCell`、`Promise` を（レコードや `Array` の中を含めて）含まない。アンカーは呼び出し先の名前 `eq`。

### Q087 同じスコープでの同名の宣言
- 関連: Q004（宣言のマージ）、§4
- 状況: Q004 は「同名の宣言が 2 つ」を E1000 とするが、モジュール直下しか検査していなかった。`const x = 1; const x = 2;`、同名の引数、関数本体の先頭で引数と同名の `const`、同じ `switch` の別の `case` での同名の宣言、レコード型やクラスの同名のメンバ、同名の型パラメータは、どれも JS として不正な出力になるか意味が曖昧になる。

## O. 検査器の健全性の穴（独立レビューの指摘）

### Q120 `this` を書ける位置
- 関連: §3.2、§4、Q029
- 状況: §4 は「`this` のクラス外での使用」だけを禁じる。static メソッドと static フィールドの初期化式の `this` はクラス（関数オブジェクト）を指し、`this.constructor("…")()` で JS の `Function` に届く。class の中の `function` 式の `this` は呼び出し方で決まり、strict モードでは `undefined` になる。フィールドの初期化式の `this` からは、宣言順で後のフィールドを初期化前に読める。
- 既定案: `this` を書けるのは、インスタンスメソッドと constructor の本体、およびその中のアロー関数だけ。それ以外（static メソッド、フィールドの初期化式、`function` 式の中）は E1000（P1）。アンカーは `this` キーワード。static メンバはクラス名で参照する（`A.n`）。

### Q121 constructor の中で初期化前のフィールドを読む
- 関連: §3.2、Q025、Q029
- 状況: Q029 は、全フィールドが constructor の直下の文 `this.f = …` で代入されることだけを求め、順序を決めていない。`this.n = this.s.length; this.s = "x";`、初期化前のメソッド呼び出し、`sink.push(this)` で、未初期化のフィールド（JS では `undefined`）が読めた。また readonly のフィールドは constructor のどこでも代入できたので、constructor の中で絞り込んだ `this.f` を後から `null` にできた。
- 既定案: constructor の本体の先頭から、初期化子のないインスタンスフィールドがすべて直下の文 `this.f = …` で代入され終わる文までを「初期化区間」とする。代入されないフィールドがあれば、最後の `this.f = …` までとする（そのときは Q029 の E2002 も出る）。
  - 区間の中では、`this` は直下の文 `this.f = …` の代入先にしか書けない。右辺、入れ子の文、アロー関数の中の `this` は E2002。アンカーは `this`。
  - 区間の中の `return` は E2002。アンカーは `return`。
  - readonly のフィールドに代入できるのは、区間の中の直下の文 `this.f = …` だけ。区間の後や入れ子の文での代入は、readonly への代入の E2002（Q075）。
  - これで区間の後の readonly フィールドは不変になり、`this.f` の絞り込み（Q025）が代入で崩れることはない。
  - 追記（確定代入の追跡）: 区間の中でも、初期化子つきのフィールドと、それより前の直下の文 `this.f = …` で代入済みのフィールドは `this.f` の形で読める（`this.n += 1` の読み取りを含む）。入れ子の文やループの中の代入は代入済みに数えない。区間の中の入れ子の関数の `this`、`this` そのものの使用、メソッドの呼び出しは、これまでどおり E2002。
  - 追記（Q133）: 区間の `return` の禁止は constructor 自身の `return` にだけ当てる。入れ子の関数の中の `return` は対象外（その関数が `this` を捕捉するのは、これまでどおり E2002）。readonly のフィールドへの直下の文での二重代入は許す。代入のたびに、そのフィールドとその下のパスの絞り込みを捨てる。

### Q122 絞り込みが解ける条件（Q025 の追記）
- 関連: §3.2、Q025、D012
- 状況: Q025 は「間に再代入があれば絞り込みは解ける」としか書かない。実装には次の穴があった。分岐の中の代入が合流後に効かない。条件の中の代入を無視する。`break` で抜けたループに、条件が偽のときの事実を当てる。クロージャが外側の絞り込みを持ち越す。クロージャの中の代入が外側の絞り込みを解かない。
- 既定案（保守的。疑わしければ絞り込まない）:
  1. 捕捉と代入: 関数の局所変数（引数を含む）のうち、入れ子の関数（アロー関数、関数式）から参照され、かつ宣言の後にどこかで代入されるものは、どこでも絞り込まない。判定は関数ごとに名前で行う（同じ関数の内側のブロックに同名の変数があれば、両方が対象になる）。関数呼び出しで局所変数が書き換わるのはこの場合だけなので、呼び出しをまたいで絞り込みを捨てる規則は別に要らない。
  2. フィールドパスは、パス上のフィールドがすべて readonly のときだけ絞り込む（Q025 のまま）。根の変数が 1 に当たれば絞り込まない。`this` の readonly フィールドは、Q121 により初期化後は不変。
  3. 代入は、その変数と、その変数を根とするパスの絞り込みを解く。分岐（`if` / `else`、`&&` / `||` の右辺、三項演算子、`switch` の各 case）の中の代入は、合流の後にも効く。`if` の一方の分岐だけが正常に終わるとき（他方が `return` / `break` / `continue` で抜けるとき）は、正常に終わる分岐の終わりの状態を引き継ぐ。前の case から落ちてくる `switch` の case は、前の case の代入の後とみなす。
  4. 条件から得る事実（`x !== null` など）のうち、条件の評価の中で代入された変数についてのものは使わない。
  5. タグつき union の型の受け手を通して `kind` に代入できない（readonly への代入の E2002）。呼び出し先がタグを書き換えると、呼び出し元の絞り込みが崩れるため。メンバのレコードの型の受け手では、`kind` はそのメンバのリテラル型なので書き換えられない。
  6. `while` の後に「条件が偽」の事実を当てるのは、本体にそのループを抜ける `break` がないときだけ。ループの入口では、本体・条件・更新式で代入される変数の絞り込みを捨てる（D012）。
- 既知の制限: `forEach` などのコールバックの中で外側の変数を代入すると、その変数は 1 により関数全体で絞り込めない。
- 実装は D051。代入による絞り込みは Q131。

### Q123 宣言とメンバに使えない名前
- 関連: §1、§10、Q010
- 状況: 生成した JS は strict モードで評価される。`package`、`yield`、`implements`、`static`、`protected` などを局所変数の名前にすると、生成した JS が構文エラーになる。生成コードの内部名（`__sts_rt`、`__sts_rt_P`、`__sts_rt_imp` など）と同名の宣言は、ランタイムを隠し、範囲検査を迂回できる。メンバ名では、`__proto__` はオブジェクトリテラルでプロトタイプを設定する。`constructor` は class のフィールドに書けない（JS の早期エラー）。static の `prototype` は class の定義で失敗する。`then` を持つ値は `await` や async 関数の戻り値で thenable として扱われる。
- 既定案: いずれも E1000（P1）。アンカーはその名前。
  - 宣言の名前（関数、引数、局所変数、分割代入の束縛名、class、interface、型の別名、型パラメータ、import の名前、関数式の名前）に、strict モードの予約語 `implements`、`interface`、`let`、`package`、`private`、`protected`、`public`、`static`、`yield`、ESM の `await`、`enum`、および `eval`、`arguments` を使えない。
  - 宣言の名前とメンバ名（レコードと Struct のフィールド、class のフィールドとメソッド）に、生成コードの接頭辞（`names.ts` の `RUNTIME_GLOBAL`。今は `__sts_rt`）で始まる名前を使えない。
  - メンバ名に `__proto__`、`constructor`、`prototype`、`then` を使えない。オブジェクトリテラルのプロパティ名 `__proto__` も同じ。レコードの `constructor` は JS では無害だが、class と同じ規則にそろえる。
  - プロパティの参照（`o.package`）と export の別名は JS として正しいので対象外。

### Q124 `await` と `break` / `continue` の位置
- 関連: §4、Q069
- 状況: async でない関数（async 関数の中の async でないアロー関数を含む）の `await`、ループと `switch` の外の `break`、ループの外の `continue` を、TS のパーサは構文エラーにせず、P1 も受理していた。生成した JS は評価の時点で構文エラーになる。
- 既定案: E1000（P1）。アンカーは `await` 式の先頭と、`break` / `continue` 文の先頭。関数の境界で数え直す（アロー関数の中の `break` は外側のループを指せない）。

### Q125 捨てられる Promise
- Q130 で置き換えた（下の式文などの形は Q130 でも拒否する）。
- 関連: §4、§8、Q074、Q140
- 状況: async 関数の呼び出しを式文で捨てると、その中のトラップは呼び出し元が終わった後の Promise の拒否になる（Q140）。
- 既定案: `Promise<T>` 型の値を捨てる次の形を E2002 にする。
  - 式文、`for` の初期化式（式のとき）と更新式、戻り値が `void` のアロー関数の式本体（Q074）。アンカーは捨てられる式の先頭。
  - 組み込みの `void` のコールバック（`forEach` など、Q032 の `prefix`）に、`Promise` を返す関数を渡すこと。実引数の型の不一致として扱い、アンカーは実引数の先頭。
  - 捨てる値の型が `Promise` を `| null` や `Array` / `ReadonlyArray` の要素として含むもの（`c ? g() : null;`、`xs.map(g);`）も同じ。

### Q126 注釈のない戻り値の推論
- 関連: §3.2、Q022、Q080
- 状況: 戻り値の注釈のないアロー関数と関数式は、`return` の型の union を戻り値型にする。`if (b) { return 1; } return "a";` から、§3.2 が許さない `f64 | string` ができた。

### Q127 型パラメータの具体化と型引数の条件（Q081 の追記）
- 関連: §3.2、§3.3、Q051、Q081、Q086
- 状況: Q081 は型パラメータそのものを `Map` のキーや `Set` の要素として通す。`function cnt<T>(xs: Array<T>) { const s: Set<T> = … }` を `T = { readonly x: f64 }` で呼ぶと、レコードの `Set` ができる（要素を参照の同一性で比べる）。`Vec<T>` / `Slice<T>` の要素、`Struct` のフィールド、`Ref<T>` / `Mut<T>`、`Vec.create<T>`、`t.eq<T>` も同じ形の穴を持つ。
- 既定案: 型パラメータがこれらの位置に現れたら、その位置の条件（キー、Copy、Struct のフィールド、借用の対象、`t.eq` で比べられる型）を型パラメータに記録する。型パラメータを具体化する箇所（関数・メソッドの呼び出しの型引数（明示と推論の両方）、`new`、型参照 `Box<P>`、型の別名）すべてについて、全部の本体を検査した後に、型引数が記録された条件を満たすかを検査する。型引数が別の型パラメータなら、条件をそちらへ引き継ぐ（変化がなくなるまで）。違反は E2002。アンカーは明示した型引数の先頭、推論なら呼び出し先の名前。`cast` / `js.decode` / `JSON.stringify` / `js.encode` の `T` は、今までどおり型パラメータを受理しない（Q084、Q128）。

### Q128 `js.encode<T>` の `T`

- 既定案: `cast` / `js.decode` と同じ条件（Q084）。違反は E2002。アンカーは明示した型引数の先頭、推論なら呼び出し先の名前（`encode`）。

### Q129 `void` 関数の `ensures`
- 関連: §9.1、Q028、Q082
- 状況: §9.1 は `ensures((r: R) => boolean)` とするが、Q082 で `r: void` は E2002 なので、`void` 関数には `ensures` を書けない。
- 既定案: 戻り値型が `void` の関数の `ensures` は、引数のない `() => boolean` を取る。引数を書くと E2002（実引数の型の不一致。アンカーは関数式の先頭）。変換は他の関数と同じでよい（戻り値を渡しても、述語は受け取らない）。

### Q130 Promise 型の式を書ける位置（Q125 を置き換える）
- 関連: §4、§8、§12、Q125、Q140
- 状況: Q125 が拒否していたのは、式文などで捨てる Promise だけだった。`const p = g();` のように変数に入れた Promise や、レコードや `Map` に入れた Promise、引数で渡した Promise は、誰も待たない。その中で起きたトラップは、`run` が正常に終わった後に現れる。`Js` 経由のタイマーを挟むと、ホストの待ち（Q140）でも拾えない。§12 は `Promise` について「`await` と `Promise.all` のみ」とする。
- 既定案: §12 を文字どおりに読む。
  - 型: `Promise` 型を書けるのは、関数の戻り値の型（関数型の戻り値を含む）の全体だけ。それ以外は E2002 で、アンカーは `Promise` の型参照の先頭。対象になるのは、変数・パラメータ・フィールド・レコードのプロパティの注釈、型引数（`Array<Promise<void>>`、`Map<string, Promise<void>>`、`Promise<Promise<T>>`）、`| null` のメンバ、型エイリアス。
  - 式: Promise を含む型（`Promise`、`Array` / `ReadonlyArray` の要素にそれを持つ型、`| null` のメンバにそれを持つ型）の式を書けるのは、次の位置だけ。それ以外は E2002 で、アンカーはその式の先頭。
    - (a) `await` のオペランド（括弧を通してよい）。
    - (b) `Promise.all` の実引数。実引数が配列リテラルなら、その要素が Promise を書ける位置になる。実引数が呼び出し式（`xs.map(g)` など、その場で配列を作る式）なら、その呼び出し式自体を書ける。変数やフィールドに入った配列は (b) に当たらない。呼び出し式を認めるのは SPEC の「配列リテラルの要素」より広い（accept/15 の `await Promise.all(xs.map(g))`）。その場で作った配列は格納されず、そのまま待たれる。
    - (c) 戻り値が `Promise` 型の関数の `return` の式と、アロー関数の式本体。戻り値の注釈がない関数では、推論した戻り値の型が `Promise` そのものでなければ拒否する（`(ys) => ys.map(g)` は拒否）。
  - `Promise.all(...)` 自体も (a) か (c) にしか書けない。三項演算子などの入れ子の式は、Promise 型の部分式で報告する（式文全体が三項演算子なら、その式文の先頭でも報告する）。
  - 組み込みの `void` のコールバックに Promise を返す関数を渡す形（`xs.forEach(g)`）は、Q125 と同じく実引数の型の不一致になる。
  - ホストの Q140 の仕組みは保険として残す。その確認は検査器を通さない std のテストで行う。
  - 追記（型引数）: ユーザーが宣言した型パラメータ（関数・メソッド・class・型の別名）の型引数に、Promise を含む型は入れられない。明示した型引数と推論した型引数の両方が対象で、Promise は関数型の中を除くどこにあっても対象になる（`Map<string, Promise<T>>`、`Result`、レコード、class の型引数を含む）。違反は E2002 で、Q127 の具体化の検査で出す。アンカーは明示した型引数の先頭、推論なら呼び出し先の名前。組み込みの型パラメータ（`Promise<T>` の `T`、`map` の戻り値の要素など）は対象外。それらは式の位置の規則で検査する。
  - 既知の制限: `await (c ? g() : h())` と `await id(g())` は拒否される（三項演算子の枝とユーザーの関数の実引数は、(a)〜(c) のどれにも当たらない）。

### Q131 代入による絞り込み（Q025 / Q122 の追記）
- 関連: Q025、Q122
- 状況: `let x: string | null = null; if (x === null) { x = "d"; } x.trim()` のような遅延初期化を、絞り込みで受理できなかった。
- 既定案: `T | null` 型の局所変数に、型が `null` を含まない値を代入したら、その後は `T` として扱う。対象は式文として単独で書いた代入（`x = e;`）と `for` の初期化式の代入だけ（Q133）。Q122 の 1 に当たる変数（入れ子の関数に捕捉され、代入される変数）は対象外。`if` の両方の分岐が正常に終わるときは、両方の終わりで同じ型に絞り込まれているものだけを残す。そのほかの合流（`&&` / `||`、三項演算子、`switch`、ループの出口）は Q122 の 3 のまま（代入があれば解く）。

### Q132 ジェネリックなメソッドの `implements`
- 関連: §3.2、Q075
- 状況: interface の `id<T>(x: T): T` を、class の `id<T>(x: T): T` で実装できなかった。型パラメータを宣言ごとの識別子で比べていた。
- 既定案: 型パラメータを位置で対応づけて比べる。個数と、対応する型パラメータの制約の一致も求める。違反は今までどおり E2002（アンカーは `implements` 句の型参照の先頭）。

### Q133 条件つきで評価される部分の中の代入と絞り込み（Q122 / Q131 の追記）
- 関連: Q025、Q122、Q131
- 状況: Q131 の代入による絞り込みを式の中の代入にも当てていたので、実行されないかもしれない代入が絞り込みとして残った。`y ?? (x = "a")` の右辺、`a?.m(x = "a")` の実引数、`do { break; } while ((x = "a") === "b")` の条件がその例で、合流の後で `x.length` を受理していた。括弧つきの左辺 `(x) = null` を、ループの入口の無効化が見落としていた。constructor の中で絞り込んだ readonly の `this.f` は、直下の文での再代入で解けなかった。
- 既定案:
  1. 代入による絞り込みは式文として単独で書いた代入と `for` の初期化式の代入だけに当てる。式の中に埋まった代入（条件式、`&&` / `||` / `??` の右辺、三項演算子の枝、実引数、`do`-`while` の条件など）は絞り込みを足さず、代入先の絞り込みを解くだけにする。
  2. 代入先は括弧を外してから見る。局所変数への代入はその変数の絞り込みを、プロパティへの代入（`this.f = …`）はそのパスとその下のパスの絞り込みを解く。絞り込みの付与、無効化、ループの入口の無効化、Q122 の 1 の判定は、同じ規則で代入先を決める。
  3. 条件つきで評価される部分（`&&` / `||` / `??` の右辺、三項演算子の枝、`?.` の呼び出し、ループの本体）の中で足された絞り込みは、合流の後に残らない。中の代入による無効化は残る。`if` と `switch` の合流は Q122 の 3 と Q131 のまま。
  - この規則で、`(x = "a") ?? "b"` の後や `if ((x = "a") === "a") { … }` の後の `x` は絞り込まれない。

### Q134 契約の式の中の副作用
- 関連: §9.1、§3.3、§7.1、§12、Q056
- 状況: §9.1 は契約の式で参照できる名前しか決めていない。`function f(x: i32): i32 { requires((x = 7) === 7); return x; }` は受理され、`f(1)` が 7 を返した。契約は観測のための式で、状態を変えるべきではない。
- 選択肢: (1) 何もしない。(2) 代入と、状態を変えうる組み込みメソッドの呼び出しを拒否する。(3) ユーザー関数の副作用も解析して拒否する。
- 既定案: (2)。`requires` / `ensures` / `invariant` の実引数の中（`ensures` の関数式の本体を含む）で、次を E6002 にする。
  - 代入と複合代入。対象は変数・フィールド・添字のどれでも同じ。アンカーは代入の式の先頭。
  - 組み込みの受け手に対する次のメソッドの呼び出し。アンカーはメソッド名。
    - `Array` の `push`、`pop`、`reverse`、`sort`、`fill`。
    - `Map` の `set`、`delete`、`clear`。`Set` の `add`、`delete`、`clear`。
    - `Vec` の `push`、`pop`、`clear`、`fill`。`Slice` の `fill`。`OwnedCell` の `take`、`put`。
    - 権限の `info`、`warn`、`error`、`writeText`、`nextF64`、`nextU32`。`js.call`、`js.await`。偽の権限の `advance`。
  - 判定はメソッド名で行い、受け手がユーザーの class なら対象外にする。
- 既知の制限: ユーザー関数・メソッドの呼び出しは拒否しない（副作用の解析が要る）。契約の中のアロー関数の本体で宣言した局所変数への代入も拒否される。

### Q110 `sts run` / `sts test` の JSON の形と出力先
- 関連: §11、Q060、Q061、Q101
- 状況: §11 は診断の JSON だけを決めている。`run` の stdout はプログラムのものなので診断を混ぜられない。`test` の結果の形、トラップの範囲の終端、`check` の複数ファイルの扱いが未定。

### Q140 await されない Promise の拒否
- 関連: §8、§9.2、§10、Q035
- 状況: `g()` のように結果を待たない async 関数の中で起きたトラップは、呼び出し元が終わった後に Promise の拒否として現れる。Node はこれを `unhandledRejection` として報告し、リスナがなければプロセスを落とす。`run` が正常終了を返した後に落ちる、`sts test` がテストを ok と報告した後に落ちる、という欠陥になる。検査器は「Promise を捨てる式文」を拒否するが、`const p = g();` のように変数に受けて待たない形は残る。
- 選択肢: (a) 実行の終了時に、保留中の拒否を 1 回だけ待って集める。待ち切れない拒否（実行の終了後に初めて起きるもの）は扱わない、(b) async 関数が返す Promise をすべて追跡して終了時に待つ（変換が大きくなる）、(c) 何もしない。
- 既定案: (a)。`main` の実行とテスト 1 件ごとに、終了後に `setImmediate` を 1 回待つ（マイクロタスクが空になった後の `unhandledRejection` が出る）。その間に集めた拒否の最初の 1 件を、`main` / テストが投げた例外と同じに扱う。トラップならトラップ（`run` は T006 などの位置つきの結果、`test` はそのテストの失敗）、それ以外はホストのエラーとして投げる。モジュールの読み込み中の拒否も同じ。STS には時間待ちがないので、終了後にさらに遅れて拒否する Promise は作れない前提。

### Q141 `cast` と整数の -0
- 関連: §3.2、Q090、Q092
- 状況: `cast<i32>(JSON.parse("-0"))` は `Number.isInteger(-0)` が真なので通り、`cast` は値をコピーしないので整数型の値が -0 のままになる（`1 / f64(x)` が -Infinity）。Q090 は整数型に -0 は存在しないとする。
- 選択肢: (a) 整数型への `cast` / `js.decode` は -0 を `err` にする、(b) +0 に直して `ok` にする（入れ子の配列やレコードの中は、コピーしない約束を破って書き換えることになる）。
- 既定案: (a)。整数型の検査で -0 は「型が違う」とする。f32 / f64 は -0 を通す。
